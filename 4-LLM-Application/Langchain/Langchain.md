`LangChain` 是一个开源的语言模型框架，它的主要作用是扩展大模型的语言能力，让大模型能够与环境进行交互，并且还能与外部数据结合。虽然通过提示词工程（Prompt Engineering）可以有效提升 LLM（大语言模型）应用的开发效率，但在这个过程中，可能会产生大量用于整合各个部分的“胶水代码”。而 `LangChain` 的作用就是将这些公共部分提炼出来，简化开发流程。

- **ChatGPT 的局限性**：

  - 扩展大模型的语言能力。
  - 让大模型与环境交互，并与外部数据结合。
  - 提炼公共部分，减少“胶水代码”的使用。

通过 `LangChain`，开发者可以更高效地构建基于大语言模型的应用，同时避免重复劳动。

LLMChain 是 LangChain 应用程序的核心构建块，下面我们来详细了解一下。

LLMChain 主要由 3 个部分组成：

1. **LLM（语言模型）**  
   - 这是 LangChain 的核心推理引擎。  
   - 它提供了多种类型的语言模型 API，接入和使用都非常方便。

2. **提示模板**  
   - 用于向 LLM 提供指令，控制 LLM 的输出。  
   - 因此，掌握如何构建提示词以及不同的提示策略非常重要。

3. **输出解析器**  
   - 将 LLM 的输出结果转换为可操作的格式，以便后续使用。  

在本节中，我们会先分别介绍这 3 个组件，然后再介绍 LLMChain，它将这 3 个组件整合在了一起。


1. LLM

在 LangChain 中，语言模型主要分为两种类型：

1. **常规语言模型（LLM）**：
   - 输入：一个字符串。
   - 输出：一个字符串。

2. **对话模型（ChatModel）**：
   - 输入：一个消息列表。
   - 输出：一个消息。

因为我们的目标是构建一个问答机器人，所以这一节的重点会放在**对话模型（ChatModel）**上。

在对话模式中，每条消息都是一个 `ChatMessage` 对象，它包含两个必不可少的组成部分：
1. `content`：这是消息的具体内容。
2. `role`：这是消息所属实体的角色。

LangChain 提供了多个对象，用来区分不同的角色。


- `HumanMessage`：这是用户发送的消息。
- `wAIMessage`：这是AI生成的消息。
- `SystemMessage`：这是系统发送的消息。
- `FunctionMessage`：这是函数调用返回的消息。

如果没有合适的角色，还可以使用`ChatMessage`类手动指定角色。不过需要注意的是，目前`ChatGLM2-6B`接入`LangChain`时，仅支持`HumanMessage`。

`LangChain`为这两种模型提供了两种预测方法：
1. `predict`：输入是一个字符串，输出也是一个字符串。
2. `predict_messages`：输入是一个消息列表，输出是一个消息。

语言模型最终输出的其实是一个带概率的单词列表。那么问题来了：我们该选哪个单词呢？

- 通常来说，选择概率最高的单词是最直接的做法。但是，如果每次都选概率最高的词，生成的文章可能会显得过于普通，缺乏新意。
- 相反，如果我们偶尔选择一些概率较低的单词，这种"灵光一现"的做法反而可能让文章变得更有趣。
- 这种随机性还意味着：即使使用相同的提示词，每次运行模型都可能得到不同的输出结果。

这个随机过程是由`temperature`参数控制的，它决定了低排名单词被选中的频率。对于文章生成任务，建议将"温度"设置为`0.8`。

1. LLMChain

我们可以把整个过程串成一个任务链，就像流水线一样工作。这个任务链的步骤如下：

1. **接收输入指令**：首先，任务链会拿到用户输入的指令。
2. **生成提示词**：接着，这个指令会被传递给一个提示模板，用来生成适合的提示词。
3. **调用大语言模型（LLM）**：生成的提示词会被传递给`LLM`，也就是大语言模型，让它来处理。
4. **解析输出**：最后，`LLM`的输出会通过一个输出解析器，整理成我们需要的格式。

简单来说，整个过程就是：**输入指令 → 提示模板 → LLM → 输出解析器**。

```python
from langchain.chains import LLMChain
temp  late  =  " 用户将输入一个类别，你需要输出该类别中的5 个对象，并以逗号分隔的列表的形式返回。
仅返回逗号分隔的列表，不要返回其他内容。"
human_template = template + " 输入：{text}，输出："
human_message_prompt = HumanMessagePromptTemplate.from_template(human_template)
chat_prompt = ChatPromptTemplate.from_messages([human_message_prompt])
chain = LLMChain(
    llm=  ChatOpenAI(model="chatglm2-6b",  openai_api_key="none",  openai_api_
base="http://localhost:8000/v1"),
    prompt=chat_prompt,
    output_parser=CommaSeparatedListOutputParser()
)
chain.run(" 颜色")
# >>> [' 红色', ' 蓝色', ' 绿色', ' 黄色', ' 紫色']
```

### 5.4.2 基本概念

LangChain 提供了很多抽象的组件，比如：

- 文档加载器
- 向量数据库
- 检索器

这些组件有两个主要特点：
1. 模块化设计
2. 使用简单

你可以根据需求：
- 把这些组件组合起来使用
- 单独使用某个组件

此外，LangChain 还内置了很多现成的任务链，专门用来处理一些常见的任务场景。

1. 文档加载器

很多基于大语言模型（LLM）的应用都需要用到特定的用户数据，比如 PDF、Word 文档等。这些数据通常不属于模型训练时用的数据集，所以在实际应用中需要单独加载。为了解决这个问题，LangChain 提供了一个专门的模块，叫做文档加载器（Document Loader）。它的作用包括：

- 加载数据
- 转换数据
- 存储数据
- 查询数据

这个模块让处理用户数据变得更加方便和高效。

文档加载器的作用是从指定的数据源中读取数据，并将其统一转换成文档格式。LangChain 提供了多种数据源的文档加载器，支持以下类型的数据加载：

- 简单的 `txt` 文件
- 网页的 `HTML` 代码
- 甚至是 `YouTube` 视频的字幕

通过这些加载器，你可以轻松地从不同来源获取数据并统一处理。


每个文档加载器都提供了一个`load`方法，它的作用是从配置好的数据源中加载文档。这个加载器还支持懒加载功能，也就是说，数据只有在真正需要的时候才会被加载到内存中。通过使用文档加载器，我们可以轻松地从各种数据源中加载数据，并将这些数据以文档的形式进行处理和分析。这种方式让处理各种文本数据变得更简单、更高效。

1. 文档转换器

在加载文档之后，通常需要对它们做一些处理，以便更好地满足实际需求。举个例子，最简单的处理方式就是把长文档切成适合模型上下文窗口的小段文本。LangChain 提供了很多内置的文档转换工具，让分割、组合、过滤这些操作变得非常简单。

具体来说：
- **分割**：把大文档切成小段，方便模型处理。
- **组合**：把多个小段文本合并成更大的块。
- **过滤**：去掉不需要的部分，保留有用的内容。

这些操作都能通过 LangChain 轻松完成。

（1）文本分割


文本分割，顾名思义，就是用来把文档的文本内容切成小块。大语言模型（LLM）在处理文本时都有一个长度限制。比如，`ChatGLM2` 的上下文大小是 8000 个 `token`。如果我们想对一份 100 页的 PDF 文件进行总结，直接把所有文本内容一次性丢给模型，肯定会因为超出模型的处理上限而报错。



最直接的方法就是设定一个最大长度（比如 `max_length`），然后把所有文档按照这个长度切分。不过，这样做有个问题：可能会把一个完整的句子切成两段，导致语义不连贯。理想情况下，我们希望切分时能把语义相关的段落保留在一起。


在 LangChain 中处理文本切分时，整个过程可以简单分为三步：

1. **切分小段落**：首先，把文本按照语义上有意义的部分切分成小段落，通常是以句子为单位。
2. **合并成大段落**：接着，把这些小段落合并成更大的段落，直到达到预设的长度阈值。
3. **继续处理后续文本**：最后，继续处理后面的小段落，创建新的文本片段，同时保持一定的重叠部分。

这样做的目的是让文本切分既符合语义逻辑，又能满足长度要求。

这里的“重叠”指的是在切割文档时，每个新文档会包含一部分前一个文档结尾的内容。这样做主要是为了让每个文档的上下文更有连贯性。举个例子：

- 当 `chunk_overlap` 的值是 `0` 时：
  - 第一个文档是 `aaaaaa`
  - 第二个文档是 `bbbbbb`

- 当 `chunk_overlap` 的值是 $\scriptstyle{\sqrt{-2}}$ 时：
  - 第一个文档是 `aaaaaa`
  - 第二个文档是 `aabbbbbb`

通过这种方式，文档之间的内容就有了重叠部分，从而增强了上下文的关联性。

推荐使用**递归文本分割器**（`Recursive Character Text Splitter`），它的工作原理是这样的：

1. 它接收一个字符列表作为参数。
2. 首先，它会尝试用列表中的第一个字符来分割文本。
3. 如果分割后发现有任何一个块太大，它就会继续用列表中的下一个字符来分割。
4. 这个过程会一直重复，直到所有块的大小都合适为止。

默认情况下，它会按照以下字符顺序进行分割：
- `[^{\mathfrak{m}}\backslash\mathfrak{n}\backslash\mathfrak{n}^{\mathfrak{n}}$`
- `"\n"`
- `" "`
- `""`

简单来说，就是先试第一个字符，不行就换下一个，直到分割得刚刚好！

除了控制分割字符之外，文本分割还可以调整以下几个关键点：

- `length_function`：这是一个用来计算段落长度的函数。默认情况下，它计算的是字符数，但通常我们会在这里传递一个词元计数器（比如用来统计单词或句子的数量）。
  
- `chunk_size`：这是每个块的最大大小，具体大小由`length_function`来测量。它表示每个块里能包含多少字符或token（比如单词、句子等）。

- `chunk_overlap`：这是块与块之间的最大重叠部分。保留一些重叠内容可以帮助保持块之间的连续性，就像滑动窗口一样。

- `add_start_index`：这个选项决定是否在元数据中包含每个块在原始文档中的起始位置。如果开启，就能知道每个块是从文档的哪个位置开始的。

通过这些设置，我们可以更灵活地控制文本分割的方式，确保分割后的内容既符合需求，又能保持上下文的连贯性。

```python
from langchain.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
load  er  =  TextLoader("filter_alltxt/2020-01-21__ 江苏安靠智能输电工程科技股份有限公司
__300617__ 安靠智电__2019 年__ 年度报告.txt")
ducument = loader.load()
text  _splitter = RecursiveCharacterTextSplitter(chunk_size=100, chunk_overlap=20, 
length_function=len, add_start_index=True)
```

3. 嵌入向量

随着数据量越来越大，信息检索的要求也越来越高，传统的基于关键词的检索方式已经不够用了。这时候，基于向量的检索技术就派上了用场，它可以作为传统检索方法的一个很好的补充。

具体来说，这种技术是怎么做的呢？

1. 首先，把数据转换成向量的形式
2. 然后，模型就能快速分析和对比这些向量
3. 最后，准确地找到相似和相关的内容

这样做的好处是显而易见的：模型处理起来更快，匹配结果也更准确。比起单纯地找关键词，这种方法能更好地理解内容的含义，找到真正相关的信息。

$$ \text{向量检索} = \text{数据转换} + \text{快速分析} + \text{精准匹配} $$

所以，当我们需要处理大量数据，或者想要更准确地找到相关信息时，基于向量的检索技术就是一个很好的选择。

向量就像是数学里的空间坐标，它既可以用来表示某个实体的位置，也可以用来计算不同实体之间的距离。我们通常会把非结构化的数据（比如文字、语音、图片、视频等）转换成向量，这个过程叫做**嵌入**（Embedding）。而**非结构化检索**，也叫**向量检索**，其实就是通过检索这些向量来找到对应的实体的过程。

简单来说：
- 向量 = 数学空间坐标
- 嵌入 = 把非结构化数据（文字、语音、图片等）变成向量
- 向量检索 = 通过向量找到对应的实体

嵌入技术之所以重要，是因为它让我们能够进行语义检索，也就是找到那些意思相近的文本或其他信息。举个例子，就像图2展示的那样，当我们在向量空间中对`男人`、`国王`、`女人`和`女王`这几个词的关系进行建模时，可以很清楚地看出它们之间的相关性，并且还能得到一个近似的等式：

- **语义检索能力**：嵌入技术让我们能够找到意思相近的内容。
- **向量空间建模**：比如在向量空间中分析`男人`、`国王`、`女人`和`女王`的关系。
- **相关性可视化**：通过建模，可以直观地看到这些词之间的关联。
- **近似等式**：最终还能得到一个近似的数学关系。

这种技术让我们能够更好地理解语言中的复杂关系。

这就是向量运算带给我们的便利和惊喜。

向量检索的应用非常广泛，主要包括以下几个领域：
- 人脸识别
- 图片搜索
- 语音处理
- 文件搜索

随着AI技术的普及和数据量的不断增加，向量检索在AI技术栈中变得越来越重要。它不仅是对传统检索技术的有效补充，还具备多模态搜索的能力。通过向量检索，我们可以更高效地处理和利用大规模的非结构化数据，从而显著提升搜索的准确性和效率。



LangChain 的 `Embeddings` 类是一个专门用来和文本嵌入模型打交道的工具。它连接了多个嵌入模型供应商，比如 OpenAI、Hugging Face 等等。这个类的设计目标是为所有模型提供一个统一的接口，方便使用。


`Embeddings` 类主要有两个功能，分别对应两个方法：

1. **嵌入文档**：这个方法可以一次性处理多个文本，适合用来处理需要被搜索的文档内容。
2. **嵌入查询**：这个方法则是专门用来处理单个文本的，通常用于处理用户的搜索请求。

为什么要分成两个方法呢？这是因为不同的嵌入模型供应商可能有不同的处理方式。具体来说：

- 有些供应商对**文档**（即被搜索的内容）和**查询**（即搜索请求本身）采用了不同的嵌入策略。
- 通过将这两个功能分开设计，可以更好地兼容各种嵌入模型的需求，适应不同供应商的实现方式。

总结一下，这种设计是为了让 `Embeddings` 类能够灵活应对不同嵌入模型供应商的要求，确保无论是文档还是查询，都能以最合适的方式进行处理。

4. 向量数据库

将非结构化数据转换成向量后，如何存储这些向量，以及如何高效地查询和检索它们？这些问题其实不需要我们从头开始解决，因为有一种专门的工具——**向量数据库**——可以帮我们搞定这些事。它的主要作用就是：

- **存储向量数据**：专门用来存放转换后的向量。
- **执行向量搜索**：快速高效地完成向量的查询和检索。

换句话说，向量数据库就是为这些任务量身定制的解决方案。

Faiss 是向量数据库领域的开创者，由 Meta 开发，专门用于高效地进行稠密向量的相似度检索和聚类。它支持多种算法，能够处理不同规模的向量集合，甚至能应对那些大到无法完全放入内存的向量集合。Faiss 的核心是用 `C++` 编写的，同时提供了完整的 Python 封装。此外，一些最常用的算法还支持 GPU 计算，进一步提升了性能。

- **核心功能**：
  - 高效进行稠密向量的相似度检索和聚类。
  - 支持多种算法，适应不同规模的向量集合。
  - 能够处理超出内存容量的超大规模向量集合。

- **技术特点**：
  - 底层使用 `C++` 编写，性能高效。
  - 提供完整的 Python 封装，便于使用。
  - 部分常用算法支持 GPU 计算，加速运算。

Faiss 的设计使其成为处理大规模向量数据的理想工具。


Faiss 提供了多种相似度搜索的方法。它的工作原理是这样的：

1. **向量表示**：每个实例都被表示为一个向量，并通过一个唯一的 ID 来标识。
2. **相似度计算**：可以使用以下三种方式来比较向量之间的相似度：
   - 欧几里得距离（L2 距离）
   - 点积
   - 余弦相似度
3. **搜索目标**：在向量数据库中，搜索的目标是找到与待对比向量最相似的向量。具体来说：
   - 如果使用 L2 距离，则寻找距离最小的向量。
   - 如果使用点积，则寻找点积最大的向量。
   - 如果使用余弦相似度，则寻找余弦相似度最大的向量。

在实际应用中，为了提升检索的召回效果和排序质量，我们通常会使用量化、Hash 或者图等检索模型来得到一个候选集（TopN）。不过，这还没完，我们还需要对这些候选集进行进一步的原始向量距离计算和比对。这个步骤在实际的生产环境和成熟的产品中特别重要，因为原始向量的存储问题总是绕不开的——毕竟这些向量通常都非常庞大。

简单来说，整个过程可以分成几步：
1. 使用量化、Hash 或图等模型来召回候选集（TopN）。
2. 对这些候选集进行原始向量距离的计算和比对。
3. 处理原始向量的存储问题，因为它们的规模通常很大。

这些步骤缺一不可，尤其是在实际应用中，它们直接影响到检索的效果和系统的性能。

在传统的信息检索中，如果单台机器的内存不够用，我们通常会采用分布式数据库来存储数据，这已经是一种很常见的做法。而在向量检索中，也会遇到类似的问题。比如，当我们需要检索数百万甚至数千万个向量时，光靠一台机器显然是不够的，而且搜索速度也会变得非常慢。所以，对于这种大规模的向量检索，采用分布式解决方案是非常必要的。这样做的好处是，我们可以充分利用多台机器的计算和存储资源，从而大大提高检索的速度和效率。

具体来说：
- **传统信息检索**：单机内存不足时，分布式数据库是常见选择。
- **向量检索**：同样面临内存和速度的挑战，尤其是处理数百万甚至数千万个向量时。
- **解决方案**：采用分布式系统，利用多台机器的资源，提升检索速度和效率。

总结一下，无论是传统信息检索还是向量检索，分布式方案都是应对大规模数据检索的有效手段。

vearch 是京东专门为 AI 领域开发的一套分布式向量搜索系统。它的功能非常强大，主要包括以下几点：

6. 任务链

在 LangChain 框架中，`链（Chain）`是一个核心的构建模块，负责执行和处理各种任务。LangChain 提供了几种不同类型的链，比如 `LLM 链`、`顺序链` 和 `路由链` 等。每种链都设计用来处理不同复杂度的任务，并且它们可以像链条一样串联起来，依次执行多个任务。下面我们详细介绍一下这些链的类型以及它们在不同场景中的应用。

1. **LLM 链（LLMChain）**：
   - 这是一个基础模型，特点是简单但功能强大。
   - 它的作用是将 `LLM` 和给定的提示结合起来，生成具体的输出。
   - 它是构建更复杂链的基础。

2. **顺序链（SequentialChain）**：
   - 如果任务的流程比较简单，只有一个输入和一个输出，那么 `简单顺序链（SimpleSequentialChain）` 是最合适的。
     - 它会按顺序连接各个子链，每个子链处理一个输入并生成一个输出。
   - 如果任务涉及多个输入或输出，那么 `常规顺序链（SequentialChain）` 更适用。
     - 在这种链中，每一步都可以接收来自上游的多个输入变量。
     - 这在处理由多个子链组合而成的复杂任务时特别有用，尤其是当多个上游链需要与下游链结合时。

3. **路由链（RouterChain）**：
   - 适用于需要多个子链处理不同类型输入的场景。
   - 它的工作原理是：
     - 首先判断哪个子链最适合处理给定的输入。
     - 然后将输入数据传递到被选中的子链中进行处理。

通过这种方式，LangChain 的链机制能够灵活应对各种任务需求，无论是简单还是复杂的场景。

通过合理地组合和配置这些链，用户可以在LangChain 框架下轻松地实现各种复杂的功能和任务。
