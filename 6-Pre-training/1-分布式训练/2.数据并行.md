## 2 数据并行

数据并行训练是一种常见的并行化方式，其核心思路是将模型复制到多个GPU上，同时将数据集切分为多个片段，每个片段被分配给一个GPU处理。这种方法可以让训练过程在多个设备上同时进行，从而提升训练速度。

在数据并行训练中，每个GPU都持有一份完整的模型副本，并根据分配到的那部分数据进行训练。当完成反向传播后，所有设备上的梯度会被汇总，用于更新模型参数，以确保多个设备中的模型参数保持同步。

本章将依次讲解三种主要的数据并行方式：朴素数据并行（`DataParallel`, 简称DP）、分布式数据并行（`Distributed Data Parallel`, 简称DDP）以及零冗余优化器数据并行（`ZeRO-DP`）。这些方法各自适用于不同的应用场景，并具有独特的优点。本节主要介绍朴素数据并行和分布式数据并行，而关于零冗余优化器数据并行的内容将在4.5节阐述。

1. 朴素数据并行

在早期的数据并行模式中，通常会采用参数服务器（Parameters Server，简称 PS）架构。这种方法主要用于单机多卡的训练场景。在 PS 架构中，GPU 被划分为两类角色：负责具体计算的被称为工作节点（worker），而专门用于梯度汇总的被称为服务器节点（server）。

为了尽量减少通信量，在实际应用中，通常会让一个工作节点同时兼任服务器节点的角色。例如，所有的梯度可以汇总到 0 号 GPU 上完成聚合操作。

需要特别指出的是，一个工作节点或服务器节点可能由多个 GPU 组成。同时，服务器节点有多种任务模式，它既可以只负责梯度的汇总，也可以在完成梯度汇总的基础上再处理全量参数的更新。

DP（DataParallel）采用的是单进程多线程的方式，非常简单易用。只需要通过一行代码：`dp_model = torch.nn.DataParallel(model)`，就能完成对模型的包装。除此之外，它的使用方式与单卡训练几乎没有区别。

由于 DP 只运行在一个进程中，因此无需手动启动多个进程。这种方式会自动完成以下操作：
- 将输入数据分发到多张显卡上；
- 在多卡上进行模型复制；
- 最后收集计算结果。

从用户的角度来看，DP 的使用可以说是“傻瓜式”的设计，非常方便。

DP 的默认配置是将 0 号 GPU 设定为主 GPU，所有的数据收集和梯度同步都在主 GPU 上完成。因此，其它 GPU 都需要与 0 号 GPU 通信，这可能会导致传输效率降低，并可能引发负载不均衡的问题。因此，尽管 DP 的使用非常便捷，但仍需留意它可能带来的负载分布不均的情况。

我们将在两块 2080Ti GPU 上，使用朴素数据并行的方法来训练一个用于 MNIST 手写数字图片分类的模型。首先，需要导入相关的函数和类。

定义一个 `LeNet` 模型。多年来，图像分类领域诞生了许多经典的卷积神经网络架构，而 `LeNet` 则是最早的卷积神经网络之一。早在 1998 年，Yan LeCun 第一次将 `LeNet` 应用于图像分类任务，并在手写数字识别中取得了显著的成果。

LeNet 利用卷积层和池化层的组合，逐步提取图像中的特征，其模型结构如图11所示。

以下代码的实现方式与此前所述架构稍有不同。这整个卷积神经网络由6个主要部分组成：

1. 首先是一个 `3×3` 的卷积层 `conv1`，它会输出6个通道的特征图，特征图的尺寸为 `30×30`。

2. 然后连接一个 `2×2` 的池化层 `pool1`，步长为2，经过池化后，特征图的空间尺寸变为 `15×15`。

3. 接下来是第二个卷积层，依然使用 `3×3` 的卷积核。该卷积会输出16个通道的特征图，其尺寸为 `13×13`。

4. 第二个卷积层之后同样接入一个 `2×2` 的池化层 `pool2`，步长仍为2。池化后，特征图的空间尺寸变为 `6×6`。

5. 接下来，将输出的四维张量转换为二维张量，把张量的 `CHW`（通道、高度、宽度）这3个维度合并成一个单一的维度。

6. 最后，使用3个线性层对特征进行变换，特征的维度会依次从 `576` 降至 `120`，再降到 `84`，最终映射到 `10` 分类。

```python
class LeNet(nn.Module):
    def __init__(self):
        super(LeNet, self).__init__()
        self.conv1 = nn.Conv2d(in_channels=1, out_channels=6, kernel_size=3)
        self.pool1 = nn.MaxPool2d(kernel_size=2, stride=2)
        self.conv2 = nn.Conv2d(in_channels=6, out_channels=16, kernel_size=3)
        self.pool2 = nn.MaxPool2d(kernel_size=2, stride=2)
        self.fc1 = nn.Linear(in_features=16 * 6 * 6, out_features=120)
        self.fc2 = nn.Linear(in_features=120, out_features=84)
        self.fc3 = nn.Linear(in_features=84, out_features=10)
    def forward(self, x):
        x = self.pool1(torch.relu(self.conv1(x)))
        x = self.pool2(torch.relu(self.conv2(x)))
        x = x.view(x.size(0), -1)
        x = torch.relu(self.fc1(x))
        x = torch.relu(self.fc2(x))
        x = self.fc3(x)
        return x
```

        optimizer.zero_grad()

2. 分布式数据并行

分布式数据并行比朴素的数据并行更为复杂，它通过采用一种名为 `Ring AllReduce` 的通信方法，通常应用于多台机器、多张显卡协同训练的场景。

- **关于 DDP**  
  DDP 是一种基于多进程的分布式处理方法。在 DDP 中，每块 GPU 都运行在一个独立的进程中并行处理任务，这种设计避免了 Python 中全局解释器锁（`GIL`）带来的瓶颈。

- **通信机制**  
  使用 `Ring AllReduce` 通信时，所有 GPU 会被环形连接起来。每个 GPU 只需要与邻近的上下游 GPU 进行通信。通过这样的设计，每块 GPU 在两次循环后就能够获取全部的全局信息。

- **优点**  
  此通信方式有效解决了负载不均衡问题，同时提升了通信效率，使分布式训练在更大规模场景下更加高效。

然而，使用 DDP 相对来说更为复杂，需要额外导入 3 个函数和类。

```python
import torch.distributed as dist
from torch.utils.data.distributed import DistributedSampler
from torch.nn.parallel import DistributedDataParallel as DDP
```

`torch.distributed` 是 PyTorch 中的子模块，专门用来提供一系列用于分布式训练的基础工具和功能。

这个模块帮助用户在多个计算节点上实现并行和分布式训练，从而提升训练速度并支持更大规模的模型。需要使用的函数是 `dist.init_process_group(backend, init_method, world_size, rank)`，它的作用是初始化分布式的进程组，并启动相关进程。这里的参数含义如下：

- `backend`：指定通信使用的后端，比如 `nccl`、`gloo` 或 `mpi`。
- `init_method`：定义如何初始化进程组。
- `world_size`：表示进程组中包含的总进程数。
- `rank`：标识当前进程在整个组中的编号。

在 PyTorch 库中，`torch.utils.data.distributed` 模块提供了一个名为 `DistributedSampler` 的类，它的主要作用是服务于分布式训练的数据采样需求。在分布式训练中，通常需要将训练数据均匀分配到多个进程中，以便每个进程可以处理各自独立的一部分数据，从而实现并行处理。`DistributedSampler` 的功能就是按照进程总数和当前进程的标识（即 rank）来对数据集进行划分，确保每个进程都能获取到互不重叠的一部分数据。

编写训练的主函数时，需要关注以下两个关键点：

1. 初始化进程组，并获取当前进程的 `rank`。这个步骤是分布式训练的基础。

2. 在创建训练数据集加载器（DataLoader）时，需要实例化一个 `DistributedSampler`，以便在数据加载时完成分布式采样工作。

完成上述两个步骤后，使用 `DistributedDataParallel` 对模型进行封装。这一步可以将模型转换为支持分布式数据并行的形式。

训练部分按照常规流程进行即可。需要特别注意的是，保存模型时只需保存 `rank==0` 的进程所持有的模型，因为该模型与其他进程持有的模型完全相同。

以下是一段对代码的通俗易懂的逐步解释，并使用Markdown格式进行组织。

```python
def main():
    # 初始化分布式训练
    dist.init_process_group("nccl")

    # 获取当前进程的 rank
    rank = dist.get_rank()
    print(f"Start running DDP on rank {rank}.")

    # 定义数据预处理
    transform = transforms.Compose([
        transforms.Resize((32, 32)),  # 图像调整到 32x32 的尺寸
        transforms.ToTensor()        # 将图像转为 Tensor 格式
    ])

    # 加载 MNIST 训练数据集
    train_dataset = MNIST("./MNIST", train=True, download=True, transform=transform)

    # 创建分布式采样器，确保在不同进程中采样的数据不重叠
    train_sampler = DistributedSampler(train_dataset, shuffle=True)

    # 创建数据加载器
    train_dataloader = torch.utils.data.DataLoader(
        train_dataset, batch_size=256, sampler=train_sampler
    )

    # 确定将模型放置在哪个 GPU 上
    device_id = rank % torch.cuda.device_count()

    # 创建模型并将其加载到对应的设备上
    model = LeNet().to(device_id)

    # 使用分布式数据并行 (DDP) 封装模型
    model = DDP(model, device_ids=[device_id])

    # 定义训练过程的参数
    epochs = 10                         # 训练轮数
    criterion = nn.CrossEntropyLoss()   # 使用交叉熵损失函数
    optimizer = optim.SGD(
        model.parameters(),
        lr=0.01,
        momentum=0.9,
        weight_decay=5e-4
    )  # 使用随机梯度下降 (SGD) 优化器

    # 开始训练
    for epoch in range(epochs):
        train_loss, correct, total = 0, 0, 0
        
        for index, (inputs, targets) in enumerate(train_dataloader):
            # 将输入和目标数据分别放到对应的设备上
            inputs, targets = inputs.to(device_id), targets.to(device_id)

            # 清空优化器的梯度
            optimizer.zero_grad()

            # 前向传播计算模型输出
            outputs = model(inputs)

            # 计算当前批次的损失
            loss = criterion(outputs, targets)

            # 反向传播更新梯度
            loss.backward()

            # 使用优化器更新模型的参数
            optimizer.step()

            # 累计损失和准确率
            train_loss += loss.item()
            _, predict = outputs.max(1)          # 获取预测结果
            total += targets.size(0)             # 累计目标样本数
            correct += predict.eq(targets).sum().item()  # 累计正确预测样本数

        # 输出当前 epoch 的损失和准确率
        print(
            f"epoch on rank {rank}: {epoch + 1} / {epochs}, "
            f"loss: {loss:.4f}, accuracy: {(100 * correct / total):.2f}%"
        )

    # 在 rank 为 0 的进程中保存模型

        torch.save(ddp_model.module.state_dict(), 'model.pth')

    # 销毁通信进程组
    dist.destroy_process_group()

# 如果脚本作为主程序执行，则运行 main 函数
if __name__ == "__main__":
    main()
```

3. 数学证明

从数学的角度来看，数据并行是一种高效的策略。如果仅使用单机单卡来进行模型训练，通常我们需要将完整的数据集依次输入模型，这种方式在处理大规模数据时效率较低。通过数据并行，我们可以将数据分成多个不重叠的子集，每个子集独立分配给不同的设备。这些设备可以同时计算前向传播和反向传播，大幅度提高训练效率。

实现数据并行的核心在于，将模型的参数在多张卡之间同步。每次设备完成各自子数据的计算后，会将梯度汇总，由此更新一组共享的模型参数。这种方式能够保证，不论设备的数量是多少，所有参与训练的设备都在优化同一个模型参数，因此在训练过程中能够保持一致性。而同步参数的操作通常依赖一些高效的通信策略，比如 `All-Reduce` 算法。在复杂的分布式场景下，会使用计算和通信重叠的技术来进一步优化性能。

通过对损失函数 `Loss` 针对参数 `𝑤` 求梯度，也就是

$$
\frac{\hat{\mathcal{O}}\mathrm{Loss}}{\hat{\mathcal{O}}w}\!=\!\frac{1}{n}\!\sum_{i=1}^{n}\!\frac{\hat{\mathcal{O}}f(x_{i},y_{i})}{\hat{\mathcal{O}}w}
$$

假设 $x_{i}$ 和 $y_{i}$ 分别表示第 $i$ 个样本的特征和标签，通过前向传播可以计算出样本 $i$ 的预测值和真实值之间的损失，记为 $f(x_{i},y_{i})$。如果数据集总共包含 $n$ 个样本，那么可以对所有样本的损失进行累加，并计算它们的平均值。之后，通过梯度下降的方法来更新模型的参数即可。

如果需要将数据分配到 $k$ 个节点上，那么每个节点分配的数据量可以表示为 $m_{k}$，这个过程本质上是在每个进程上计算对应的梯度。当每个进程上分配的训练样本数量相等时，最终计算出的结果就是 $k$ 台机器的平均梯度和，从数学关系上看，这是恒等的。

$$
\frac{\hat{\sigma}\mathrm{Loss}}{\hat{\sigma}\omega}\!=\!\sum_{i=1}^{k}\!\frac{m_{k}}{n}\!\frac{\partial\!\left[\!\frac{1}{m_{k}}\!\sum_{i=m_{k-1}+1}^{m_{k-1}+m_{k}}f(x_{i},y_{i})\!\right]}{\hat{\sigma}w}\!=\!\sum_{i=1}^{k}\!\frac{m_{k}}{n}\!\frac{\hat{\sigma}l_{k}}{\hat{\sigma}w}\!=\!\frac{1}{k}\!\sum_{i=1}^{k}\!\frac{\hat{\sigma}l_{k}}{\hat{\sigma}w}
$$

4. 梯度同步

数据并行是大多数情况中使用最广泛的方法，只要模型可以在CPU/GPU上运行即可。其实现方式通常是基于小批量数据的处理。在训练过程中，各节点分别计算梯度的平均值，然后使用这些平均梯度来更新模型参数。

在每次使用一个小批量数据完成训练后，所有节点都需要同步梯度或已更新的参数，这样可以确保所有节点上的模型状态保持一致。目前常见的同步方式主要有两种。

- 批量同步并行（Bulk Synchronous Parallel，BSP）：在这种方式下，当所有节点完成每个小批量数据的训练后，才会进行数据的同步操作。这种方法能够确保所有节点的模型权重保持一致，但同步时可能会出现因等待其他节点而产生的延迟。

- 异步并行（Asynchronous Parallel, ASP）：在异步并行中，每个节点会以异步的方式同步数据。当某一轮计算完成后，节点只需将自己的权重参数发布出去，然后利用接收的权重更新自身，随即开始下一轮训练。这种方式能够避免节点之间的等待问题，但可能会导致权重参数更新滞后，从而降低整体的学习效率。

我们来梳理一下数据并行的操作流程，主要包含以下几个步骤：

1. **分布式系统与专用GPU**  
   在一个分布式系统中，存在多个计算单元，例如多个GPU。同时还需要一个专用的GPU，用于收集所有的梯度。

2. **模型参数初始化**  
   在训练开始时，模型的所有参数会被复制到每一个计算用的GPU上，以确保所有GPU的参数在初始化时完全一致。

3. **数据分配**  
   训练数据会被均匀地分配到每个计算GPU中，确保各个GPU都有可处理的独立数据块。

4. **前向与反向传播**  
   每个GPU使用它分配到的数据，执行前向传播和反向传播操作，分别计算出一组梯度值。

5. **梯度收集与聚合**  
   所有计算GPU在完成梯度计算后，会将各自的梯度发送给专用的梯度收集GPU。在收集GPU上，这些梯度会通过累加操作进行聚合。

6. **参数更新**  
   聚合后的梯度会从梯度收集GPU发送回所有计算GPU。各计算GPU根据这些统一的梯度结果，更新自己上面的模型参数。经过更新后，所有GPU的模型参数会再次保持一致状态。

通过这种方法，可以充分利用多个GPU来并行处理数据，从而提升模型训练的效率。同时，这种设计能够确保所有计算节点上的模型参数始终保持一致。在数据并行（DP）模式中，大部分通信压力集中在服务器节点，因为服务器需要与所有GPU进行通信。这使得服务器的通信量与GPU数量成线性增长，因此DP通常更适合单机多卡的场景。

相比之下，分布式数据并行（DDP）采用了一种名为`Ring AllReduce`的NCCL操作，它能够将通信压力均匀分散到所有GPU上。这样，每个GPU所需处理的通信量是一个固定常量，不会因为GPU数量的增加而变大。因此，DDP能够支持跨机器训练，非常适合用于大规模的分布式训练任务。

数据并行因为实现起来简单且实用性强，所以被广泛应用。不过，这并不意味着它没有缺点。在数据并行的场景下，每张显卡都会存储一份完整的模型，这使得显存容量成为模型规模的限制因素。如果在模型训练过程中能减少显存的占用，就有可能支持训练更大的模型。

在数据并行中，系统中如果有 $N$ 张显卡，那么会存在 $N$ 份模型参数。但实际上，这 $N - 1$ 份是冗余的。一个非常关键的问题是：每张显卡是否有必要都存储完整的模型呢？能否让系统中仅保留一份完整的模型，每张显卡只需要存储 $1/N$ 的参数？如果这样实现的话，显卡数量增加时，每张显卡所需的显存就会减少，从而支持训练更大规模的模型。

5. 梯度累积

在这里介绍一个新概念——**梯度累积**，它与数据并行有些相似。

- 梯度累积的核心思想是，将一个大批量的数据拆分成多个小批量数据。对于每个小批量数据，依次进行前向传播和反向传播，然后将每次计算得到的梯度累积起来。当所有小批量数据的梯度都累加完成后，统一进行模型参数的更新。

- 从原理上看，梯度累积和数据并行非常相似，但梯度累积的实现相对更为简单。**数据并行**是在空间上展开的，它将一批数据拆分为多个小张量，分配给多个设备进行并行计算。每个设备独立计算其对应部分的梯度，然后将这些梯度汇总后更新模型参数。而**梯度累积**可以看作是时间上的数据并行，它将同样的数据拆分为多个小张量，按顺序输入到同一个设备中进行串行计算，累积梯度后再更新模型。

梯度累积是时间上的分批计算，数据并行则是空间上的并行计算，这是它们的主要区别。

当总的批量大小保持一致，并且数据并行的并行度与小批量的累加次数相等时，从数学的角度来看，数据并行和梯度累积是完全等价的。在梯度累积方法中，多个小批量的梯度通过累加来计算，而且下一个小批量的前向传播不依赖于上一个小批量的反向传播，因此整个计算过程能够顺畅进行。

在实际应用中，梯度累积帮助解决了许多问题：

1. **显存节约**  
   在单卡训练时，梯度累积通过将大批量分解为等效的多个小批量，从而有效减少显存需求。这非常适合显存有限的设备使用。

2. **降低梯度同步开销**  
   在数据并行训练中，梯度同步的开销往往是一个难题。当梯度同步变成稀疏操作时，随着设备和机器数量的增多，梯度的全局同步开销会显著增长。然而，利用梯度累积可以缓解这一问题，进而提高数据并行的加速比。

在 PyTorch 中实现梯度累积的代码实现较为简便，示例如下：

```python
for i, (features, target) in enumerate(dataloader):
    # 前向传播
    output = model(features)
    loss = criterion(output, target)    
    # 反向传播
    loss.backward()    
    # 每两个小批量更新一次, 以及最后一个小批量更新
    if (i+1) % 2 == 0 or (i+1) == len(dataloader):
        optimizer.step()        
        optimizer.zero_grad(set_to_none=True)
```
