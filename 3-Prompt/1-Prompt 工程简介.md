
在传统的自然语言处理研究中，通常会遵循“预训练-微调-预测”这一流程。具体步骤是：首先使用大规模的语料库对模型进行预训练；接着对具体的下游任务进行微调；最后，利用微调后的模型来完成预测任务。

然而，随着语言模型的规模不断扩大、能力逐渐增强，一种全新的方法开始流行起来——“预训练-提示预测”。这种方式省去了复杂的微调过程，而是直接基于预训练后的模型，通过精心设计的 `Prompt`（提示）来引导模型适应下游任务。图 3.1 展示了这一流程的具体形式。


在这种新方法中，`Prompt` 的设计对模型的表现有着明显的影响。因此，如何高效地编写 `Prompt` 逐渐成为一个重要的研究方向，而这个研究领域被称为 Prompt 工程。本节将深入介绍 Prompt 工程的定义和核心概念，并讨论它在自然语言处理领域的应用及其重要性。

### 3.1.1 Prompt 的定义

在生成式人工智能模型中，`Prompt` 是指用来引导模型完成特定任务的输入指令。这种指令通常以自然语言的形式表达，作用在于清楚地描述模型需要执行的任务，从而帮助生成目标内容，比如文本、图像或者音频等。

如图3.2所示，经过精心设计的 `Prompt` 可以帮助模型实现多种功能，比如：

1. 当指令清晰地要求进行情感分类时，模型能够准确地分析出文本中包含的情感。  
2. 当指令提出某个特定主题的创作需求时，模型能够生成富有创意的诗歌。  

此外，在多模态模型的应用中，`Prompt` 还可以加入画面描述等信息，用于引导模型生成相应的视觉内容。

Prompt 的用途相当广泛，不仅局限于执行“文本到文本”的任务。由于这本书的重点在于语言模型，这一章节会特别聚焦于文本生成模型，并深入探讨如何通过精心设计的 Prompt，引导模型生成满足特定任务需求的文本输出。

### 3.1.2 Prompt 工程的定义

Prompt 工程（Prompt Engineering），也被叫作提示工程，是一种专注于设计和优化与生成式人工智能模型交互的`Prompt`的技术。本质上，这项技术通过精心构造`Prompt`，把新的任务重新表述为模型在预训练阶段已经熟悉的形式。这样，模型就能利用它自身的泛化能力去完成这些新任务，而无需为特定任务进行额外的训练。

Prompt 工程的效果很大程度上取决于两个关键点：

1. 对预训练模型的性能和特性有深入的理解。
2. 能够准确把握任务需求，设计合适的`Prompt`。

只要构造出合适的`Prompt`输入给大语言模型，模型就能帮助我们高效完成各种任务。

如图3.3所示，通过对 `Prompt` 进行优化，原本的 `Prompt` 被改进为一种更全面和更规范的形式。这种经过优化的 `Prompt` 能显著提高模型生成回答的质量。因此，在使用大语言模型时，设计出高质量且全面的 `Prompt` 至关重要，因为它会直接决定输出内容是否有价值。

一个设计良好的 `Prompt` 通常包含以下四个基本元素：

1. **任务说明**  
2. **上下文**  
3. **问题**  
4. **输出格式**

任务说明——向模型明确提出具体的任务要求。任务说明应当清晰、直接，并尽可能详细地描述期望模型完成的任务。

- 上下文是指提供给模型的与任务相关的背景信息，目的是帮助模型更好地理解任务并找到解决方案。

- 它可以包含一些特定的知识前提、目标受众的背景信息、与任务相关的示例，或者任何能让模型对任务理解更加透彻的内容。

- **问题**——指的是清楚地告诉模型用户具体的需求或需要处理的信息。这部分内容要直接和用户的查询或任务相关，以确保为模型提供一个清晰的起点。问题可以用直接提问的方式表述，也可以通过隐含的陈述句来展现用户可能存在的潜在疑问。

- **输出格式**是指模型在回答时展示内容的具体形式。它可能涉及到回答的排版方式，还可能包括是否需要满足一些特定的细节要求，比如让回答变得更加简洁或是补充更多详细信息。

- 举个例子，可以要求模型将输出内容以 `JSON` 格式进行展示。

Prompt 的效果主要受四个核心元素的影响，这些元素包括：任务说明、上下文、问题以及输出格式。这些要素需要仔细设计和合理搭配，它们共同构成了Prompt 工程的核心。

在这个基础上，Prompt 工程中还包含很多有用的技巧和方法，比如上下文学习（`In-Context Learning`）和思维链（`Chain of Thought`）等。如果把这些技巧和技术结合起来用，就能显著提高 Prompt 的质量，从而更高效地引导模型生成符合特定任务需求的输出。

关于上下文学习的具体内容，会在第3.2节详细讨论；思维链相关的内容将在第3.3节中介绍；至于Prompt的使用技巧，将在第3.4节中深入探讨。

随着 Prompt 的内容变得越来越丰富和复杂，输入到模型的 Prompt 长度也因此不断增加。这不可避免地引发了两个问题：

1. 模型的推理速度变慢；
2. 推理成本随之上升。

因此，在提升模型性能的过程中，有效地控制和优化 Prompt 的长度显得尤为重要。具体来说，需要尽可能减少输入到大型模型中的 Prompt 长度，同时确保不会对模型性能产生影响。

为了应对此问题，LLMLingua 提出了一个新颖的由粗到细的 Prompt 压缩方法。这种方法能够在确保语义完整的前提下，将 Prompt 的长度压缩到原来的大约二十分之一，同时几乎不对模型的性能产生影响。

此外，随着 RAG 技术被广泛应用，模型需要处理的上下文信息量显著增多。为应对这一问题，FIT-RAG 技术通过高效压缩检索到的内容，将上下文长度缩减至原来的约 $50\%$，但依然能够保持性能的稳定。这种方法为处理大规模上下文信息提供了一种可行的解决方案。

### 3.1.3 Prompt 分词向量化


设计好一个合适的 `Prompt` 后，用户会将它输入到大语言模型中，希望模型生成理想的结果。然而，大语言模型实际上并不能直接理解这些文字。在将 `Prompt` 输入模型之前，需要先把它拆解成由 Token 组成的序列。这里的 Token 是表示语义的最小单位，通常对应一个特定的词，每个 Token 都有唯一的 Token ID 来标识。这个把文本转换成 Tokens 的过程被称为分词（Tokenization）。


比如，参照图 3.4，一句话“小浣熊吃干脆面”经过分词处理后，会被拆分成一个个 Token 组成的序列，而序列中的每个 Token 都有对应的 Token ID。

![](https://gitee.com/Ace_bb/static_resource_cloud/raw/master/大模型基础/第3章Prompt工程/images/eaa75b72c8e05f68d94e65a2d78d9330f2c51c6d70807699ce4e1be119caa167.jpg)

图3.4: 分词与嵌入的过程，以DeepSeek-V2-Chat 模型的分词器为例。

需要注意的是，一句话可能会有多种不同的拆分方式。比如，上面的句子可以被拆分成“小, 浣熊, 吃干, 脆面”。但是，像这样的拆分方式可能会让语义变得模糊或者不够清楚。因此，分词是一项充满挑战的工作，我们需要认真设计分词的方法。

为了实现高效的分词，主要需要以下两个步骤：

1. 构建一个词表，这个词表包含了所有大语言模型能够识别的 `Token`。
2. 根据该词表对句子进行拆分处理。

在构建大语言模型的词表时，需要使用分词器。分词器的运行原理依赖于一些分词算法，比如 `BBPE`、`BPE` 和 `WordPiece` 等。这些算法通过分析语料库中的词频等信息，将文本拆解成多个 `Token`。下面以 `BBPE`（Byte-Level Byte Pair Encoding）算法为例，介绍它的分词过程。`BBPE` 的主要流程可以分为以下四个步骤：

1. **初始化词表**：首先，将所有字符按其底层编码拆解成一个个字节，并把这些单独的字节编码用作初始词表中的 `Token`。

2. **统计词频**：计算词表里所有 `Token 对`（也就是相邻 `Token` 组合）出现的次数。在最开始时，这些 `Token 对` 指的是相邻字节的组合。

3. **合并高频 Token 对**：寻找出现频率最高的 `Token 对`，将其合并为一个新的 `Token`，并将这个新生成的 `Token` 加入到词表中。

4. **迭代合并**：反复执行统计词频和合并高频 `Token 对` 的操作，循环进行这一过程，直到词表的大小达到预定标准或完成规定次数的合并。

我们可以通过调整迭代次数等方法来控制分词的粒度，而分词的粒度不同会直接决定词表的大小。词表的大小会对模型的表现产生重要影响，具体体现在以下几个方面：




1. **词表过小的影响**：
    - 如果词表特别小，比如只有256个`Token`，每个`Token`只是一个单字节。虽然这可以覆盖所有GBK编码的汉字和英文字符，但也会带来一些问题：
        - 模型在区分一些形态相似但含义不同的词汇时会变得困难，这会削弱它理解复杂语义的能力。
        - 生成的序列会变得非常长，从而降低效率。


2. **词表太大带来的影响**：

- 当词表过大时，虽然能够包含更多的长尾词汇，但也会带来以下问题：
  - 模型可能无法深入学习这些词汇，这会影响其理解能力。
  - 难以有效识别同一个单词在不同时态或形态之间的关联。

因此，在设计词表时，我们需要在以下两点之间找到平衡：
- 既要确保词表可以覆盖范围广泛的词汇；
- 又要保证语义上的细致精确。

只有这样，才能让大语言模型既具备丰富的词汇知识，又能够正确理解和生成包含复杂语义的文本。

具体来说，正如图3.4所展示的那样，为了让模型更好地理解词语的含义，同时减少生成常用词时需要的Token数量，词表会将语料库中高频出现的词或短语纳入其中，并将它们单独处理为一个Token。例如，“干脆”会直接表示为一个Token。

为了解决 Token 分布的问题并缩小词表大小，构建词表时会加入一些特殊的 Token。这些 Token 不仅能单独表示特定语义，还可以通过两两组合来表达语料库中一些低频出现的生僻字。比如，“浣”这个字可以用两个 Token，分别是“`æµ`”和“`£`”，组合起来进行表示。

通过这样的设计，词表既可以覆盖常用的高频词汇，又能够通过多个Token的组合来灵活表示各种罕见的字符。从这里可以看出，词表的构建在某种程度上受到了“先验知识”的影响。而这些“先验知识”正是人类通过长期积累和整理语料库得来的结果。

每个大语言模型都会有一个专属的分词器，它的主要作用是把文本拆解成一定的单位。为了做到这一点，分词器会使用一个词表，并依据这个词表对文本进行分割。分词器的效果如何，会直接对模型性能产生影响。

一个好的分词器不仅可以明显提高模型对文本语义的理解能力，还能提升处理速度，同时降低对计算资源的消耗。优质的分词器通常具备以下几个特点：



1. **准确性**：能够准确地找到文本中的重要关键词和短语，这对模型理解语义信息非常关键。

2. **效率**：分词器的效率会直接影响模型的训练和推理表现。一个高效的分词器可以对文本中的`Token`进行优化压缩，从而大大减少模型处理数据所需的时间。

几点主要观察如下：

1. 以 `DeepSeek` 和 `Qwen` 为代表的中文开源大语言模型，在中文分词方面做了专门的优化。根据数据统计显示，平均每个 `Token` 能表示大约1.3个汉字（也就是说，每个汉字只需要大约0.7个 `Token`）。此外，某些高频用词或成语甚至可以直接映射为一个单独的 `Token`，这一点大大降低了模型所需的分词数量。

2. 相比之下，那些使用英文为主要语料进行训练的模型（比如 `GPT-4` 和 `LLaMA` 系列），在处理中文分词时表现较差，分词的效率也比较低。而在英文语境下，由于某些后缀（例如 `ly` 或 `ist`）本身可以直接作为单独的 `Token`，一个英文单词通常需要 1 个或更多的 `Token` 来表示。

每个 `Token` 都能承载更多的语义信息，因此在表达相同的文本内容时，模型只需要生成较少的 `Token`。这种减少不仅让语言模型的输出更加高效，还极大地提高了推理的速度。

通过这种对比，我们可以清晰地看到不同模型分词器在处理不同语言时的效率，这对于选择合适的模型和优化模型性能具有重要的指导意义。

完成分词后，得到的这些 Token 会通过模型的`嵌入矩阵`（Embedding Matrix）转换成固定大小的表示向量。这些向量序列会被直接传入模型，使模型能够对它们进行理解和处理。

在生成阶段，模型会先根据输入的向量序列，计算出词表中每个词对应的概率分布。接着，模型会依据这些概率分布，选出并输出相应的`Token`。最终，这些`Token`会被转化回对应的文本内容。

文本会先用分词技术拆解成一个个`Token`，然后这些`Token`会被转化成特征向量。在高维空间中，这些向量用来表示文本。通过这样的处理方式，语言模型能够抓住文本中更深层次的语义结构。这种方法还可以帮助模型高效地理解和学习各种语言结构，不管是简单的词汇，还是复杂的句子结构和语境。

### 3.1.4 Prompt 工程的意义

Prompt 工程是一种既高效又灵活的方法，可以用来完成各种自然语言处理任务。借助这种方法，我们无需对模型进行微调，就能够成功实现任务目标，这样可以有效避免微调过程中产生的高昂成本。通过设计精巧的 Prompt，我们能够充分发挥大型语言模型的潜力，在多个领域展现出强大的能力，比如以下几个方面：

- 垂直领域任务
- 数据增强
- 智能代理

这种方法展现了大型语言模型在多种场景中的广泛适用性和卓越表现。

#### 1. 垂域任务

利用 Prompt 工程来引导大语言模型完成特定领域的任务，可以省去针对每个任务单独微调的步骤。这种方法不仅能节省微调过程中消耗的大量计算资源，还能减少对标注数据的需求。借助这样的方式，大语言模型在处理垂直领域任务时变得更加高效。

比如，在处理 Text-to-SQL 任务时，我们可以使用 Prompt 工程的技巧，直接引导大语言模型根据用户输入的文本生成高质量的 SQL 查询，而不需要借助有监督的微调。通过基于 GPT 模型的 Prompt 工程方法，不仅能够在 Spider 榜单上取得突破性成果，还能超越传统的微调方法。

此外，在涉及知识密集型任务的问答场景中（例如 MMLU 及多个领域相关任务），利用 Prompt 工程的方法同样表现出色，甚至达到了最佳效果。

#### 2. 数据增强

使用 Prompt 工程结合大语言模型进行数据增强，不仅能够提高现有数据集的质量，还可以生成全新的高质量数据。这些数据可以被用来训练或优化其他模型，并通过合成数据的方式，将大语言模型的能力“蒸馏”到小模型之中。

比如，我们可以通过设计合适的提示，促使 ChatGPT 模型生成带有丰富推理步骤的数据集，这样可以提升金融领域中 Text-to-SQL 模型的推理能力。此外，通过精心设计提示，还能生成复杂指令类型的数据集，比如 `Alpaca` 和 `Evol-Instruct` 这样的数据集。

将这些合成的数据集用于微调小型模型时，可以在保持模型参数量较小和计算成本较低的情况下，尽可能接近大型模型的性能。

#### 3. 智能代理

通过使用Prompt工程，能够将大语言模型设计为一种智能代理（Intelligent Agent，IA）。智能代理，也被称为智能体，是指一种可以感知环境、自主执行动作以完成目标，并通过学习或获取知识来提升表现的系统。在感知环境、采取行动和学习新知识的每个过程中，Prompt工程都扮演着至关重要的角色。

比如，斯坦福大学曾用GPT-4构建了一个虚拟的西部小镇。在这个小镇里，有多个基于GPT-4的智能代理，它们会根据自己的角色和目标自主行动。这些智能体能够相互交流、处理问题，并推动小镇的整体发展。而这个虚拟小镇之所以能顺利运作，完全得益于Prompt工程的支持。

本节内容讲解了什么是 `Prompt`，以及 `Prompt` 工程的定义和重要性，并强调了 `Prompt` 在大语言模型应用中的关键作用和巨大潜力。同时，我们还将进一步对这一主题进行深入探讨：
