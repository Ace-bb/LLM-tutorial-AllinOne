

OpenAI 已经推出了多个大语言模型，每个模型都有自己独特的特点和能力。最早的 GPT-3 模型，它的索引名是 `davinci`。后来，OpenAI 又发布了 Codex 系列模型，这个系列的第一个模型是基于 GPT-3 进行微调的，参数规模达到了 120 亿，名字叫 `Code-davinci-001`。再后来，这个 120 亿参数的模型演变成了 OpenAI API 中的 `Code-cushman-001`。

接下来，OpenAI 发布了一篇关于指令微调的论文，其中提到的有监督微调部分对应了两个模型：
- `Instruct-davinci-beta`
- `Text-davinci-001`

这些模型都是 OpenAI 在不同阶段推出的重要成果。

有了这两项技术之后，OpenAI 进一步通过以下步骤训练出了一系列模型：

1. **语言模型 + 代码训练**：首先，他们结合语言模型和代码训练，开发出了 `Code-davinci-002` 模型。
2. **有监督指令微调**：接着，通过有监督的指令微调，训练出了 `Text-davinci-002` 模型。
3. **基于人类反馈的强化学习**：最后，利用基于人类反馈的强化学习方法，训练出了 `Text-davinci-003` 和 `ChatGPT` 模型。

在这段内容中，我们重点讨论了大语言模型的两种核心能力：**泛化能力**和**思维链推理能力**。让我们先来聊聊**泛化能力**。

1. **泛化能力**指的是：
   - 当模型通过大量指令进行微调后，它能够对从未见过的新指令也能给出有效的回答。
   - 这种能力对模型的实际应用非常重要，因为用户会不断提出新的问题，模型必须能够很好地应对这些未知任务。

2. 需要注意的是：
   - 这种泛化能力并不是一开始就有的，而是随着指令数量达到一定规模后逐渐显现出来的。

总结来说，泛化能力是模型能够适应新任务的关键，而它的形成依赖于足够多的指令微调。

其次，我们来聊聊大语言模型在复杂推理任务中使用的**思维链（Chain of Thought, CoT）**能力。简单来说，初代的`GPT-3`模型在这方面表现得比较弱，但经过专门训练的`Code-davinci-002`和`Text-davinci-002`模型却展现出了非常强的思维链推理能力。有趣的是，这种能力很可能是通过**代码训练**获得的。

- **初代GPT-3的局限性**：早期的`GPT-3`模型没有经过代码训练，所以它的思维链推理能力非常有限。
- **代码训练的作用**：随着大量代码数据的输入（比如`Codex`模型使用了`159GB`的代码数据），新一代模型逐渐展现出了强大的推理能力。

总结一下，代码训练可能是提升模型思维链推理能力的关键因素。

至于原因，推测可能在于代码本身具有极高的逻辑性。与普通文本相比，代码必须严格遵循逻辑规则，否则将无法执行。因此，代码可以看作一种具有高度逻辑性的文本语料。人类创造了诸如`C`、`Python`、`Java`等编程语言，并编写了海量的代码。这些代码被喂给了大语言模型，使模型在学习过程中逐渐掌握了代码背后的抽象能力与逻辑能力。这种对于逻辑和抽象的学习可能是`ChatGPT`等模型表现“智能”的原因。此外，由于代码中含有大量注释信息，这些注释与代码之间形成数据对，意外地实现了多模态对齐的工作，从而进一步提升了模型的推理能力。

总之，让大语言模型展现出智能行为的关键，可能离不开以下三个因素：

1. **代码训练**：这能让模型具备很强的逻辑思维和抽象能力。
2. **指令微调**：通过调整模型，让它更好地理解和执行人类的指令。
3. **基于人类反馈的强化学习**：通过人类的反馈，进一步强化模型对指令的响应和遵循能力。

这些因素共同作用，让模型变得更“聪明”。下面我们会详细聊聊这些内容。

### 2.4.1 代码生成模型Codex


- **Codex** 是 GitHub Copilot 背后的代码生成模型。
- **Copilot** 支持十几种编程语言，能够根据自然语言生成代码。

  - 而 Copilot 则支持多种编程语言。

Codex 是一个基于 `GPT` 的语言模型，它在 GitHub 上公开的代码数据上进行了微调。虽然 `GPT-3` 的核心优势在于它可以通过上下文学习直接推理，而不需要额外的微调，但 Codex 是 `GPT-3` 的一个具体应用，因此它针对特定场景进行了优化。

总结一下：
- GPT-3 可以根据注释生成简单的 Python 代码。
- 这个能力很让人兴奋，因为 GPT-3 并没有专门训练过代码数据。
- Codex 的研究者们进一步探索了这个功能，专注于从注释生成 Python 函数代码。
- 他们还通过单元测试来自动评估生成的代码是否正确。

代码生成任务和自然语言生成任务有一个明显的区别：在自然语言生成中，结果通常需要人工来评估，但在代码生成中，结果可以直接由机器来评估。为了更准确地测试模型的性能，Codex 的研究者们创建了一个包含 164 个编程问题的数据集，叫做 `HumanEval`。这个数据集主要用于测试代码生成模型在以下几个方面的能力：

1. 对编程语言的理解能力
2. 对算法的实现能力
3. 解决数学问题的能力

通过这个数据集，研究者们可以更好地评估模型在代码生成任务中的表现。

在现实生活中，编程往往不是一步到位的，通常需要多次迭代和修改。在评估模型时，我们可以让模型生成多个答案，只要其中有一个能通过单元测试就算成功。Codex 的研究者在这种设定下对模型进行了测试：

1. 如果只允许生成一个答案，初版的 120 亿参数的 Codex 模型能够解决 $28.8\%$ 的问题。
2. 为了进一步提升性能，研究者收集了一个与评估策略更匹配的数据集，并在其上微调，得到了 Codex-S 模型。
   - 此时，即使只生成一个答案，模型也能解决 $37.7\%$ 的问题。
   - 如果允许生成 100 个答案，只要有一个通过就算成功，模型能够解决 $77.5\%$ 的问题。

然而，在实际编程中，不可能让模型生成 100 个答案再由用户选择。因此，论文中提出了一种排序算法：通过计算生成结果的平均概率，选择概率最大的结果。这种方法能够解决 $44.5\%$ 的问题。

1. 评估指标

在评估语言模型的效果时，我们经常会用到一种叫 `BLUE` 的指标。这个指标主要看的是模型生成的序列和真实的序列在某些子序列上的相似程度。它是一个“模糊匹配”的指标，也就是说，不需要完全一致也能得分。

不过，在生成代码的任务中，`BLUE` 分数可能会遇到一些问题。这是因为：

- 即使生成的代码和目标代码在某些子序列上看起来一致，也不意味着生成的代码一定能正确运行。
- 代码的正确性不仅仅取决于表面的相似性，还取决于它是否能达到预期的效果。

所以，`BLUE` 分数在代码生成任务中可能并不是一个完美的评估标准。

在Codex的论文中，研究者们使用了一个叫做`pass@k`的指标来评估模型的表现。这个指标中的“k”表示模型可以生成`k`个不同的结果，只要其中有一个结果能够通过测试，就算作通过。

不过，直接计算`pass@k`的结果可能会不太稳定。为了解决这个问题，研究者们会让模型一次性生成`n`个结果（其中`n > k`），然后从这`n`个结果中随机抽取`k`个，看看其中是否包含正确答案。如果抽中的`k`个结果中有正确答案，就记下正确答案的个数为`c`。

总结一下：
- `k`：模型生成的`k`个结果中，只要有一个通过测试就算成功。
- `n`：模型一次性生成的`n`个结果（`n > k`）。
- 随机采样：从`n`个结果中随机抽取`k`个，检查其中是否有正确答案。
- `c`：抽中的`k`个结果中正确答案的个数。

这种方法可以更稳定地评估模型的性能。

具体的计算公式为

![](https://gitee.com/Ace_bb/static_resource_cloud/raw/master/LLMBook/LLMBOOK1/images/1754188045f77ad2f00254898cde82f2d4ec08a6998bed0fd6715ff6eef6ce21.jpg)

为了提高计算效率，可以将公式简化，并转换成如下函数代码。

```python
def pass_at_k(n, c, k):
    """
    :param n: 生成的结果总数
    :param c: 正确结果的数目
    :param k: 从n个结果中选择k个结果
    """
    if n - c < k: return 1.0
    return 1.0 - np.prod(1.0 - k / np.arange(n - c + 1, n + 1))
```

Codex 的作者使用 HumanEval 数据集来评估函数的正确性。这个数据集有以下几个特点：

- 包含 **164 个手写编程问题**，每个问题都包括：
  - 函数的签名
  - 注释
  - 函数体
  - 若干个单元测试

这些评估数据集是**人工编写**的，而不是从网上直接获取的。原因是：网上的代码很可能已经被包含在训练数据集中了，如果直接用网上的数据评估，结果可能会有偏差。

2. 代码微调

Codex 的训练数据是从 GitHub 上收集的，具体来说，是在 2020 年 5 月从 5400 万个代码仓库中提取的。这些数据包含了 179GB 的 Python 文件。不过，在正式使用之前，这些数据经过了严格的过滤，去掉了以下几类内容：

- 可能是自动生成的文件。
- 平均每行长度超过 100 个字符的文件。
- 最大行长度超过 1000 个字符的文件。
- 二进制文件。

经过这些清洗步骤后，最终的数据集大小缩减到了 159GB。

由于代码的单词分布和自然语言的文本分布有很大不同，代码中包含了大量的空格、缩进和换行符。为了更好地处理这些特点，Codex 在训练时引入了一组特殊的词元，用来表示不同长度的空格。这样做的好处是，可以节省大约 $$30\%$$ 的词元使用量。


Codex 是基于 `GPT-3` 模型训练出来的。不过，有个挺有意思的现象：在预训练模型的基础上再进行微调，并没有让最终效果有明显提升，只是让模型收敛的速度变快了。


论文中提到，在生成代码时使用了**核采样**的方法。具体来说：

1. **普通采样的局限性**：
   - 普通采样每次都会选择经过`softmax`计算后概率最大的词元。
   - 但这种方法并不能保证整个序列的最终概率最大，也就是说，它不是全局最优的。
   - 另一个问题是，如果每次都选择平均概率最大的值，生成的结果会变得非常固定，缺乏多样性。

2. **改进方法**：
   - 通常的改进方法是使用**树搜索**（也叫`Beam Search`）。
   - 这种方法会维护一定数量的当前最优候选词，并逐步向下层执行。
   - 虽然这样做会增加一些计算量，但它可以一次性给出多个解，提高了结果的多样性。

3. **核采样的实现**：
   - 核采样在每个时刻会对候选词计算一个概率。
   - 然后按照概率对词元进行降序排列。
   - 保留那些累加概率达到`0.95`的所有词元，从而在保证多样性的同时，也能控制生成结果的质量。

通过这种方式，核采样在生成代码时能够更好地平衡多样性与质量。

4. 局限性分析


Codex 的表现虽然不错，但也存在一些明显的局限性。

1. **训练样本的利用率问题**  
   Codex 的训练效率并不高。它的训练数据集包含了 GitHub 上大量公开的 Python 代码，总计达到数亿行。相比之下，即使是经验丰富的开发者，在他们的职业生涯中也不太可能接触到如此庞大的代码量。有趣的是，一个刚完成入门级计算机科学课程的优秀学生，可能比 `Codex-12B` 解决更多的问题。

2. **长文本处理能力不足**  
   Codex 在处理长文本时表现较差。研究者构建了一个由 13 个基础块组成的数据集，每个块都按照特定规则修改输入内容。例如，对于输入的变量 `x`、`y`、`z`、`w`，模型需要依次执行以下 3 个块：
   - 让 `y` 加 3；
   - 让 `x` 和 `w` 都减去 4；
   - 返回 4 个数的乘积。

   然而，生成的代码结果并不正确。更具体地说，当文档字符串（`docstring`）中链接的块数量增加时，模型的性能呈指数级下降。这与人类程序员的行为不同，人类程序员能够处理任意长度的程序链。


```python
def do_work(x, y, z, w):
    t = y + 3
    u = x - 4
    v = z * w
    return v
```

最后，Codex 生成的代码可能会存在以下问题：

1. **语法错误或未定义的代码**：它生成的代码有时可能不符合语法规则，或者使用了未定义的代码片段。
2. **调用未定义或超出范围的函数、变量和属性**：Codex 可能会调用一些在代码库中不存在或超出当前范围的函数、变量或属性。
3. **难以解析复杂规范**：随着规范变得越来越长、越来越高级或涉及系统级的内容，Codex 的解析能力会明显下降。

这些问题限制了 Codex 在处理复杂任务时的表现。

综上所述，Codex 虽然在某些方面表现非常出色，但它仍然存在一些需要改进的地方：

- **样本利用率**：Codex 在处理样本时还不够高效。
- **长文本处理**：当面对较长的文本时，Codex 的表现还有待提升。
- **全局理解**：Codex 在理解整体上下文方面还有不足。
- **数学计算**：Codex 在数学计算方面的能力也需要进一步加强。

这些问题需要在未来的研发过程中逐步解决和改进。

### 2.4.2 强化学习

在介绍InstructGPT之前，咱们得先聊聊强化学习是啥。强化学习也是机器学习的一种，但它跟有监督学习、无监督学习和自监督学习不太一样。它的目标是让机器学会在特定环境下，通过做出一连串动作，来获得最大的长期收益。

简单来说，强化学习其实就是一套做决策的系统。正因如此，它在很多游戏里都派上了用场。举个大家都知道的例子：`AlphaGo`。它就是把强化学习和专家系统结合得特别好，最后打败了好几位人类顶尖高手。

1. 基本概念

强化学习让模型（也叫智能体）通过与环境的互动来完成任务。如图7所示，整个过程是这样的：

1. 智能体首先会感知当前环境的状态，记作 $S_{t}$。
2. 接着，智能体会根据它的计算能力做出决策，并执行一个动作，记作 $A_{t}$。
3. 这个动作会对环境产生影响，导致环境发生变化，同时产生一个奖励 $R_{t+1}$ 和一个新的状态 $S_{t+1}$，这些信息会反馈给智能体。
4. 然后，智能体会根据新的环境状态 $S_{t+1}$ 再次进行感知和决策，整个过程就这样循环下去。

简单来说，就是智能体不断与环境互动，通过感知、决策、执行、反馈的循环来逐步优化自己的行为。

在强化学习中有一些基本概念。

（1）随机过程

抛开智能体不谈，环境通常也是动态的，它会随着某些因素的变化而不断演变，这个过程是随机的。随机过程是用来描述一连串随机现象的动态关系的，它研究的是那些随时间变化的随机现象。举个例子，假设有一辆汽车要通过一个十字路口，它可以选择直行、左转、右转或者调头，这就是一个随机过程。定量描述这个随机过程，就是要确定汽车直行、左转、右转和调头的概率分别是多少。

- **随机现象**：在某个时刻 $t$，汽车的状态（比如加速度、车速、位置等）是一个随机取值。这些状态可以用一个向量 $\pmb{S}_{t}$ 来表示。
- **状态集合**：所有可能的状态组合在一起，就构成了状态集合 $S$。
- **随机过程的关键要素**：
  - **状态**：这是随机过程的核心。
  - **状态转移的条件概率分布**：在 $t$ 时刻的状态 $\pmb{S}_{t}$ 通常取决于之前的状态 $\boldsymbol{{S}}_{1},...,\boldsymbol{{S}}_{t}$。因此，下一时刻的状态 $\boldsymbol{S}_{t+1}$ 的概率可以表示为 $P(\mathbf{{S}}_{t+1}\mid\boldsymbol{{S}}_{1},...,\boldsymbol{{S}}_{t})$。

通过这种方式，我们可以定量地描述随机过程中状态的变化规律。

![](https://gitee.com/Ace_bb/static_resource_cloud/raw/master/LLMBook/LLMBOOK1/images/da3bce1dd03588ee31cf8425db864dc0267c9f6c1575475eb286ef493fdabcdb.jpg)
图7 强化学习中智能体与环境的交互

（2）马尔可夫性质

马尔可夫性质说的是，对于一个随机过程，如果我们知道它现在的状态以及过去的所有状态，那么它的未来状态只跟当前状态有关。换句话说，未来状态的条件概率分布只依赖于当前状态，跟过去的状态（也就是这个过程的“历史”）是独立的。举个例子，就像开车的时候，汽车在某个时刻的状态（比如速度和方向）只取决于上一时刻你踩了多少油门和方向盘怎么转。

结合马尔可夫性质，计算下一时刻状态 $\boldsymbol{S}_{t+1}$ 的公式就可以简化为：
$$P(\mathbf{S}_{t+1}\mid\boldsymbol{S}_{t})$$

简单总结一下：
- 未来状态只依赖当前状态，跟过去无关。
- 公式从复杂的条件概率简化为 $P(\mathbf{S}_{t+1}\mid\boldsymbol{S}_{t})$。

虽然根据马尔可夫性质，下一刻的状态只取决于当前状态，不受过去状态的影响，但这并不意味着和历史完全没有关系。原因如下：

1. **当前状态包含历史信息**：虽然 $t+1$ 时刻的状态只与 $t$ 时刻的状态有关，但 $t$ 时刻的状态本身已经包含了 $t\!-\!1$ 时刻的状态信息。
2. **链式传递**：通过这种链式关系，历史信息实际上被传递到了当前时刻。

换句话说，虽然每一步只依赖当前状态，但当前状态本身已经“记住”了之前的状态，所以历史信息并没有完全消失。

所以马尔可夫性质实际上简化了计算，只要当前状态可知，就不再需要所有的历史状态了。

（3）马尔可夫过程

具有马尔可夫性质的随机过程被称为**马尔可夫过程**，通常用一个元组 $(S,P)$ 来表示。这个元组包含两个部分：

1. **$S$**：表示随机过程中所有可能状态的集合，状态的数量是有限的。
2. **$\pmb{P}$**：表示状态转移矩阵，它定义了状态之间的转移概率。

假设总共有 $n$ 个状态，那么状态转移矩阵 $\pmb{P}$ 就是一个 $n \times n$ 的矩阵。矩阵中的每个元素表示从一个状态转移到另一个状态的概率。具体来说：

- 矩阵的第 $i$ 行第 $j$ 列元素，表示从状态 $S_{i}$ 转移到状态 $S_{j}$ 的概率。

用公式表示就是：
$$
P_{ij} = P(S_{j} | S_{i})
$$

简单来说，状态转移矩阵 $\pmb{P}$ 描述了系统从一个状态跳到另一个状态的可能性。

$$
P={\left[\begin{array}{l l l}{P(S_{1}\,|\,S_{1})}&{\cdots}&{P(S_{1}\,|\,S_{n})}\\ {\vdots}&{\ddots}&{\vdots}\\ {P(S_{n}\,|\,S_{1})}&{\cdots}&{P(S_{n}\,|\,S_{n})}\end{array}\right]}
$$

（4）马尔可夫奖励过程

如果在马尔可夫过程的基础上，再加上一个奖励函数 `r` 和一个折扣因子 `γ`，就能得到一个叫做**马尔可夫奖励过程**的东西。它由四个部分组成，用元组表示就是 `(S, P, r, γ)`。

- **奖励函数 `r`**：这个函数的作用是告诉我们，当系统转移到某个状态 `S` 时，会得到多少奖励。
  
举个例子，假设我们给一辆自动驾驶车辆安排了一个任务：先洗车，然后加油，最后回家。那么：
- 当车辆到达洗车店时，它会得到一个奖励；
- 当它到达加油站时，又会得到一个奖励；
- 最后，当它回到家时，还会再得到一个奖励。

这样，整个过程就可以用马尔可夫奖励过程来描述。

折扣因子 `γ` 的取值范围是 `[0,1)`。我们引入折扣因子是因为未来的利益往往存在不确定性，有时候我们希望更快地获得奖励，所以需要对未来的利益打一个折扣。具体来说：

- 当 `γ` 越接近 `1` 时，表示我们更关注长期的累积奖励。
- 当 `γ` 越接近 `0` 时，表示我们更关注短期的奖励。

换句话说，`γ` 的大小决定了我们对未来奖励的重视程度。

在马尔可夫奖励过程中，每个状态的期望回报被称为这个状态的**价值**，而所有状态的价值组合在一起就形成了**价值函数**。价值函数的输入是一个状态，输出则是这个状态的分值。

举个例子，假设我们有三个状态：洗车、加油和回家。我们可以这样理解它们的价值：

- 洗车的价值比加油低，因为洗不洗车其实影响不大。
- 加油的价值又比回家低，因为不加油可能会导致无法回家。
- 回家的价值最高，因为最终目标就是回家。

基于这种逻辑，我们可以定义每个状态的价值如下：
- 洗车的价值：$r(\Dot{\eta}\Dot{\mathrm{z}}\Dot{\mathrm{4}})=1$
- 加油的价值：$r(\text{加油})=3$
- 回家的价值：$r(\text{回家})=5$

这样，价值函数就清晰地反映了每个状态的重要性。

（5）马尔可夫决策过程

上面提到的随机过程都是环境自己变化的。但如果有一个外部的刺激，也就是智能体的动作，那么环境的下一个状态就会由当前状态和智能体的动作共同决定。马尔可夫决策过程就是在马尔可夫奖励过程的基础上，再加入智能体的动作。它由以下元组表示：$$(S,\,P,\,A,\,r,\,\gamma)$$，其中：

- `A` 表示动作的集合。
- 奖励函数和状态转移函数都与 `A` 有关。

智能体采取的动作是由策略 `π` 决定的，公式表示为：$$\pi(a\,|\,s)=P(A_{t}=a\,|\,S_{t}=s)$$。这个公式的意思是，在状态为 `s` 的情况下，智能体选择动作 `a` 的概率。

在马尔可夫决策过程中，价值函数可以分为两类：**状态价值函数**和**动作价值函数**。

1. **状态价值函数**：
   - 它表示从某个状态 `s` 开始，按照策略 `π` 行动时，能够获得的**期望回报**。
   - 用公式表示为：$$V^{\pi}\left(s\right)=E_{\pi}[G_{t}\:|\:s]$$

2. **动作价值函数**：
   - 它表示在策略 `π` 下，对当前状态 `s` 执行某个动作 `a` 后，能够获得的**期望回报**。
   - 用公式表示为：$$Q^{\pi}\big(s,a\big)\!=\!E_{\pi}[G_{t}\,|\,s,a]$$

简单来说：
- 状态价值函数关注的是**从某个状态出发**的长期收益。
- 动作价值函数关注的是**在某个状态下执行某个动作**的长期收益。

2.PPO 算法介绍

了解了前面的概念后，我们正式来聊聊 ChatGPT 的 RLHF 训练中用到的近端策略优化（Proximal Policy Optimization，PPO）算法。这个算法是 OpenAI 的 John Schulman 等人在 2017 年提出的，所以它直接被用在了 ChatGPT 的训练中。

PPO 算法的核心思想其实很简单：
- 在更新策略（可以理解为模型）时，它会限制新策略和旧策略之间的差异。
- 通过这种方式，PPO 能让模型的更新过程更加稳定。

简单来说，PPO 就是通过控制策略变化的幅度，来避免更新过程中出现不稳定的情况。

具体来说，PPO 算法用了两个神经网络：
- 一个叫 `Actor`（策略网络），负责执行动作；
- 另一个叫 `Critic`（价值网络），负责处理奖励。

每次迭代时，PPO 会做以下几件事：
1. 从环境中采样一批数据；
2. 用这批数据更新策略参数和价值函数参数；
3. 在更新过程中，限制策略的更新幅度，避免出现太大的变化，导致不可恢复的问题。

这种限制是通过控制新旧策略之间的 KL 散度（Kullback-Leibler 散度，用来衡量两个概率分布的差异）来实现的，确保它不超过设定的阈值。

在代码实现中，PPO 用了一个剪裁函数 `clip` 来达到这个目的。

$$
L(\theta)\!=\!\mathrm{E}[\operatorname*{min}(r_{t}(\theta)A_{t},\,\mathrm{clip}(r_{t}(\theta),1\!-\!\varepsilon,1\!+\!\varepsilon)A_{t})]
$$

其中：
- $\theta$ 是策略的参数。
- $r_{t}(\theta) = \frac{\pi(\theta)}{\pi(\theta_{old})}$ 表示新策略与旧策略的比值，其中：
  - $\pi(\theta)$ 是新策略。
  - $\pi(\theta_{old})$ 是旧策略。
- $A_{t}$ 是优势函数，用于衡量当前策略的好坏。
- `clip` 是剪裁函数，用于限制策略更新的幅度。
- $\varepsilon$ 是允许的误差范围，用于控制策略更新的稳定性。

优势函数用于衡量在给定状态下采取某个动作相对于平均水平能好多少，其计算方法通常是用动作价值函数减去状态价值函数，即

$$
A(s,\,a)\!=\!Q(s,\,a)\!-\!V(s)
$$

- `$Q(s,\,a)$` 表示的是：当你处于状态 `$s$` 时，采取动作 `$a`，然后继续按照策略 `$\pi$` 行动，最终能获得的期望回报。
- `$V(s)$` 表示的是：当你处于状态 `$s$` 时，完全按照策略 `$\pi$` 行动，最终能获得的期望回报。

简单来说：
- `$Q(s,\,a)$` 关注的是“在某个状态下做某个动作后，未来能得到的回报”。
- `$V(s)$` 关注的是“在某个状态下，按照策略行动后，未来能得到的回报”。

在强化学习中，有三个核心概念特别重要：**优势函数**、**价值函数**和**策略函数**。它们各自有不同的作用，但又相互配合。

1. **优势函数**：它的作用是衡量在某个状态下执行某个动作的效果，看看这个动作比平均水平好多少还是差多少。这个信息对更新策略非常有帮助。

2. **价值函数**：它用来评估策略的效果，具体分为两种：
   - **状态价值函数**：衡量某个状态的价值。
   - **动作价值函数**：衡量在特定状态下执行某个动作的价值。

3. **策略函数**：它决定了在给定状态下，每个动作被选择的概率。简单来说，它直接告诉智能体在某个状态下应该怎么行动。

这三个函数虽然功能不同，但共同构成了强化学习的核心框架。

在强化学习的众多算法中，有三个关键概念经常被一起使用。这些算法通常会同时学习两个东西：**策略函数**和**价值函数**。

- **学习价值函数**：通过这个步骤，算法能更好地理解环境的变化规律。它可以帮助智能体判断在某个状态下采取某个动作的价值有多大。
- **学习策略函数**：这一步则是为了让算法找到更好的动作选择方式，从而提升智能体在环境中的表现。

通过把这两个函数结合起来使用，强化学习算法就能更有效地解决各种复杂的问题。

接下来定义两个网络—PolicyNet 和ValueNet，分别对应PPO 算法中的Actor 和Critic。

```python
class PolicyNet(th.nn.Module):
    def __init__(self, state_dim, hidden_dim, action_dim):
        super(PolicyNet, self).__init__()
        # 定义第一层全连接层，输入维度为状态维度，输出维度为隐藏层维度
        self.fc1 = th.nn.Linear(state_dim, hidden_dim)
        # 定义第二层全连接层，输入维度为隐藏层维度，输出维度为动作维度
        self.fc2 = th.nn.Linear(hidden_dim, action_dim)
    def forward(self, x):
        # 使用ReLU 作为激活函数
        x = F.relu(self.fc1(x))
        # 对第二层的输出使用softmax 函数，得到一个概率分布
        return F.softmax(self.fc2(x), dim=1)

```python
def compute_advantage(gamma, lambda_, td_delta):
    # 将td_delta 从PyTorch 张量转化为numpy 数组
    td_delta = td_delta.detach().numpy()
    # 初始化优势值和优势列表
    advantage_list = []
    advantage = 0.0
    # 逆序遍历td_delta 中的每一个元素
    for delta in reversed(td_delta):
        # 利用公式计算每个时间步的优势
        advantage = gamma * lambda_ * advantage + delta
        # 将优势添加到优势列表中
        advantage_list.append(advantage)
    # 将优势列表中的元素顺序反转
    advantage_list.reverse()
    # 将优势列表转化为PyTorch 张量
    return th.tensor(advantage_list, dtype=th.float)

        # 初始化Actor 和Critic
        self.actor = PolicyNet(state_dim, hidden_dim, action_dim).to(device)
        self.critic = ValueNet(state_dim, hidden_dim).to(device)
        # 设置对应的优化器

        self.critic_optimizer = th.optim.Adam(self.critic.parameters(), lr=critic_lr)

        self.gamma = gamma
        self.lambda_ = lambda_
        self.epochs = epochs  # 使用一个完整序列的数据来多轮训练

def update(self, transition_dict):
    # 从转换字典中提取状态、动作、奖励、下一状态和结束标志
    states = th.tensor(transition_dict["states"], dtype=th.float).to(self.device)
    actions = th.tensor(transition_dict["actions"]).view(-1, 1).to(self.device)
    rewards = th.tensor(transition_dict["rewards"], dtype=th.float).view(-1, 1).to(self.device)
    next_states = th.tensor(transition_dict["next_states"], dtype=th.float).to(self.device)
    dones = th.tensor(transition_dict["dones"], dtype=th.float).view(-1, 1).to(self.device)
    
    # 计算TD目标和TD误差
    td_target = rewards + self.gamma * self.critic(next_states) * (1 - dones)
    td_delta = td_target - self.critic(states)
    
    # 计算优势函数
    advantage = compute_advantage(self.gamma, self.lambda_, td_delta.cpu()).to(self.device)
    old_log_probs = th.log(self.actor(states).gather(1, actions)).detach()
    
    # 进行多轮网络更新
    for _ in range(self.epochs):
        # 计算新的动作概率
        log_probs = th.log(self.actor(states).gather(1, actions))
        ratio = th.exp(log_probs - old_log_probs)
        
        # 计算PPO的两种surrogate函数
        surr1 = ratio * advantage
        surr2 = th.clamp(ratio, 1 - self.eps, 1 + self.eps) * advantage  # 截断
        
        # 计算Actor和Critic的损失
        actor_loss = th.mean(-th.min(surr1, surr2))  # PPO损失函数
        critic_loss = th.mean(F.mse_loss(self.critic(states), td_target.detach()))
        
        # 清空优化器的梯度
        self.actor_optimizer.zero_grad()
        self.critic_optimizer.zero_grad()
        
        # 反向传播损失，并执行一步优化
        actor_loss.backward()
        critic_loss.backward()
        self.actor_optimizer.step()
        self.critic_optimizer.step()

def moving_average(a, window_size):
    # 计算累积和，np.insert 用于在数组第一个位置插入0
    cumulative_sum = np.cumsum(np.insert(a, 0, 0))
    # 计算每个窗口的平均值
    midd le  =  (cumulative_sum[window_size:]  -  cumulative_sum[:-window_size])  /  window_size
    # 为了处理开始和结束位置不足窗口大小的部分，独立计算它们的平均值
    # np .arange(1, window_size - 1, 2) 创建一个从1 开始，到window_size - 1 为止，步长为2 的等差数组
    # np.cumsum(a[:window_size - 1])[::2] / r 计算的是开始位置的平均值
    r = np.arange(1, window_size - 1, 2)
    begin = np.cumsum(a[:window_size - 1])[::2] / r
    # np.cumsum(a[:-window_size:-1])[::2] / r 计算的是结束位置的平均值
    # [::-1] 是为了将结果翻转，因为我们是从后向前计算的
    end = (np.cumsum(a[:-window_size:-1])[::2] / r)[::-1]
    # 将开始、中间和结束的部分连接起来，得到最终的滑动平均值
    return np.concatenate((begin, middle, end))

2. **优质对话范例的标注成本高**  
   - 这些范例需要人工专门标注，成本非常高。  
   - 因此，未来在某些特殊领域，如果积累了足够多的优质对话范例，可能会跳过预训练这一步，直接使用这些范例进行监督学习。

总结来说，直接使用优质对话范例进行训练目前存在语言多样性不足和成本高的问题，但在特定领域，未来可能会有更高效的方法。

1. 构造训练数据集

在为大语言模型创建微调数据集时，有几个关键点需要我们特别注意：

1. **数据来源的选择**  
   首先，我们需要找到合适的数据来源。这些数据可以从相关领域收集，或者通过抓取的方式获取。如果我们的目标是让模型完成某个特定任务，那么数据集中的文本必须与这个任务紧密相关。

2. **数据集的质量**  
   数据质量非常重要。在准备数据时，我们需要仔细检查和清洗数据，确保数据集里没有无关的文本或其他干扰信息（也就是“噪声”）。

3. **数据集的规模**  
   数据集的规模也是一个需要考虑的因素。一般来说，数据集中的文本数量应该在几千到几十万条之间。只有足够多的数据样本，模型才能更好地学习特定任务的规则和模式。

4. **数据的相关性和可泛化性**  
   最后，数据集中的数据需要具备相关性和可泛化性。这意味着数据应该在特定的微调任务上具有代表性，但也不能是简单的重复。

通过以上几点，我们可以确保微调数据集的有效性，从而帮助模型更好地完成任务。

目前，微调数据集通常采用指令跟随格式、多轮对话格式和其他辅助格式。

（1）指令跟随格式

这是一种用户输入指令，模型根据指令要求输出结果的格式。举个例子，`Alpaca-52k` 数据集就是这种格式，它包含了 52,000 条指令数据。这类数据集通常以 `json` 文件格式存储。

指令跟随格式有两种类型，第一种是“指令/ 输出”格式，例如：

```json
{"instruction": " 解释量子力学是什么？","outp ut": " 量子力学（Quantum Mechanics），为物理学理论，是研究物质世界微观粒子运动规律的物理学分支，主要研究原子、分子、凝聚态物质，以及原子核和基本粒子的结构、性质的基础理论。它与相对论一起构成现代物理学的理论基础。"
}
```

第二种是“指令/ 输入/ 输出”格式，例如：

```json
{"instruction": " 将这个句子翻译成法语","input": " 我喜欢读书和旅行。","output": "J'aime lire et voyager."
}
```

在用指令跟随格式的数据训练大语言模型时，数据的组织形式是“一问一答”或“一指令一输出”。具体来说：

1. **输入部分**：问题和指令会被当作提示词（prompt）输入到模型中。
2. **输出部分**：模型生成的答案就是对应的输出。

不过，在计算损失值（loss）时，有一个重要的细节需要注意：

- 必须屏蔽掉填充词（`pad token`）的部分，因为这些词是用来对齐序列长度的，并不包含实际意义，所以不应该影响损失的计算。

简单来说，训练过程就是让模型学会根据输入的问题或指令，生成正确的输出，同时忽略那些无意义的填充词。

（2）多轮对话格式

这是一种用户和模型通过对话形式进行交互的方式，模型通过多轮对话来满足用户的需求。举个例子，`ShareGPT` 数据集就是这种格式的典型代表，它包含了大量用户与聊天机器人之间的对话记录。

的对话记录。

```json
"conversations": [
    {"from": "human", "value": " 你是谁？"},
    {"from": "gpt", "value": " 我是ChatGPT，..."},
    {"from": "human", "value": " 你能做什么？"},
    {"from": "gpt", "value": " 我可以和你聊天。"},
    {"from": "human", "value": "" 你好" 用英语怎么说？"},
    {"from": "gpt", "value": "" 你好" 的英文是"Hello""},
]
```

这种对话的形式并不是模型可以直接处理的。语言模型需要的是输入“一段话”然后输出“一段话”，所以上面这种格式的数据可以转换成下面这 3 条训练样本：

1. 输入：`一段话`  
   输出：`一段话`

2. 输入：`另一段话`  
   输出：`另一段话`

3. 输入：`第三段话`  
   输出：`第三段话`

通过这种方式，对话数据就能被转换成适合模型训练的形式了。


1. `<sos>human: " 你是谁？"<sep>gpt: " 我是ChatGPT，..."<eos>`

2. `<sos>human: " 你是谁？"<sep $\mid>$ gpt: " 我是ChatGPT，..."<sep>human:" 你能做什么？"<sep>gpt:" 我可以和你聊天。"<eos>`

3. `<sos>human: " 你是谁？"<sep>gpt: " 我是ChatGPT，..."<sep>human:" 你能做什么？"<sep>gpt:" 我可以和你聊天。"<sep>human:"" 你好" 用英语怎么说？"<sep>gpt: "" 你好" 的英文是"Hello""<eos>`


### 解释：
- 每个对话片段都以 `<sos>` 开始，表示对话的开始。
- `human:` 表示人类用户的问题或输入。
- `gpt:` 表示 ChatGPT 的回复。
- `<sep>` 用于分隔不同的对话部分。
- `<eos>` 表示对话的结束。

### 示例：
1. 第一个对话片段：
   - 人类问：“你是谁？”
   - ChatGPT 回答：“我是ChatGPT，...”

2. 第二个对话片段：
   - 人类问：“你是谁？”
   - ChatGPT 回答：“我是ChatGPT，...”
   - 人类接着问：“你能做什么？”
   - ChatGPT 回答：“我可以和你聊天。”

3. 第三个对话片段：
   - 人类问：“你是谁？”
   - ChatGPT 回答：“我是ChatGPT，...”
   - 人类接着问：“你能做什么？”
   - ChatGPT 回答：“我可以和你聊天。”
   - 人类又问：“‘你好’用英语怎么说？”
   - ChatGPT 回答：“‘你好’的英文是‘Hello’。”


这种处理方式虽然简单，但也存在一些问题：

1. **数据利用率低**：一段完整的对话会被拆分成多条训练数据，导致大部分数据都是填充词，实际有用的信息很少。比如，上面提到的3条样本中的第一条，实际对话内容很短，后面直到达到`max_length`的部分全是填充词。

2. **数据重复膨胀**：训练数据的量会大幅增加，具体来说，数据量会变成“总会话数量 $\times$ 平均轮次”。这种大量的重复内容会降低训练效率。

总结一下，虽然这种方法操作简单，但会带来数据利用率低和重复膨胀的问题，影响训练效果。

GPT 这类纯解码器的语言模型有两个主要特点：

1. **因果型注意力机制**：它的注意力机制是因果（Casual）型的，就像图11 展示的那样。简单来说，每个 `token` 只能关注到它之前的 `token`，而不能看到它后面的内容。

2. **单向生成**：由于这种因果性，模型在生成文本时是单向的，只能从左到右逐步生成，无法同时考虑未来的信息。

这两个特点让 GPT 这类模型在生成文本时更加专注于当前上下文，但也限制了它对全局信息的把握能力。

大语言模型有两个关键点需要注意：

1. **上下文信息**：模型能够看到当前 token 的上文信息，也就是它前面的内容。

2. **位置编码的特点**：
   - 它的位置编码只包含了 token 的顺序信息，没有其他额外的指代信息。
   - 不过，后面我们会提到的 GLM 系列模型的位置编码更强大，它不仅可以表示 token 的顺序，还能用来表示生成文本片段（span）的位置等更多含义。

这样改写后，内容更加口语化，结构也更清晰，便于理解。

基于前面提到的两点，我们可以换个思路：通过设计新的注意力机制和位置编码，把多轮对话的输入格式改成这样：


Q1<sep>A1<eos>Q2<sep>A2<eos>Q3<sep>A3<eos>


具体来说：
- 每轮对话都用 `<sep>` 分隔问题和答案
- 每轮对话结束后用 `<eos>` 标记结束

在计算损失函数时，我们只需要关注答案部分，也就是：
- `A1<eos>`
- $\mathrm{A}2{<}\mathrm{eos}{>}$
- $_{\mathrm{A}3<\mathrm{eos}>}$

这样做的好处是：
- 可以把整个会话打包成一条样本
- 实现会话级别的训练

这种方法既保留了对话的上下文关系，又简化了训练过程。

在这个过程中，模型的输出和指令输入会不断交替进行，逐步生成完整的对话内容。这种方法的好处是，它充分利用了预训练语言模型的强大生成能力，能够快速生成大量对话数据。

2. **标注和筛选**：对生成的对话数据进行人工标注和筛选，确保数据的质量和适用性。

通过这种方式，我们就能高效地构建出符合需求的多轮对话数据集。

2. 有监督指令微调

AI 的核心目标之一，是让模型具备强大的**泛化能力**，也就是说，即使面对从未见过的任务，模型也能表现得很好。在自然语言处理（NLP）领域，预训练模型在这方面取得了很大的进展。比如，像 `GPT-3` 这样的模型，它可以根据自然语言的描述完成任务，但生成的内容有时可能不太可控。

为了解决这个问题，研究人员发现了一种叫**指令微调**（Instruction Fine-Tuning，简称 `IFT`）的技术。通过 `IFT`，模型可以更好地理解并响应指令，同时减少对大量示例的依赖。具体来说，`IFT` 可以在多种任务上对基础模型进行微调，包括：

- 情感分析
- 文本分类
- 内容摘要

这些任务都是 NLP 领域的经典任务。通过 `IFT`，模型在这些任务上的表现得到了显著提升。

在数据量方面，虽然 OpenAI 拥有大量的真实用户指令数据，但我们也可以通过合成数据来生成大量样本用于模型训练。在构建指令数据集时，主要有两种方法：

1. **从已有的标注数据集中提取数据**：
   - **优点**：可靠性高，因为这些数据是人工标注的，准确性和可用性有保障。
   - **缺点**：需要更多人工努力，将“文本–标签”对转换为“指令–输出”对。

2. **通过大语言模型生成输出**：
   - **优点**：能快速获得给定指令的期望输出，减少人工标注的工作量。
   - **缺点**：生成结果可能受到模型自身偏见的影响，存在一定风险。

因此，哪种方法更可靠并没有绝对答案，需要根据具体需求和数据可用性来综合考虑：
- 如果有足够的人力资源进行数据标注，从已有的标注数据集中提取可能是更好的选择。
- 如果人力资源有限，但需要快速生成大量数据，使用大语言模型生成输出的方法可能更合适。

然而，即使语言模型经过了IFT（指令微调），它仍然可能生成一些没用或不安全的回答。比如，模型可能会给出无效的回应，比如总是说“我不知道”；或者对敏感话题做出不安全的回答。为了解决这个问题，研究人员用了一种叫**有监督微调（Supervised Fine-tuning，SFT）**的技术。具体来说，他们会在高质量的人工标注数据上对基础语言模型进行微调，这样模型就能生成更有效、更安全的回应。

- SFT 和 IFT 其实是密切相关的，IFT 可以看作是 SFT 的一个子集。
- SFT 的主要目标是处理那些和安全相关的主题，而不是像 IFT 那样专注于指令特定的主题。

简单来说，SFT 是为了让模型在面对敏感或复杂问题时，表现得更加可靠和安全。

1. 指令（Instruction）

需要注意的是，`IFT` 和 `SFT` 并不会给模型带来新的能力，因为所有的能力其实在预训练阶段就已经具备了。`IFT` 的作用更像是“解锁”或“激发”这些能力，毕竟 `IFT` 的数据量比预训练数据少得多。通过 `IFT`，`GPT-3` 模型会分化出不同的技能方向：

- 有些模型更擅长上下文学习，比如 `text-davinci-003`。
- 有些模型更擅长对话，比如 `ChatGPT`。

另外，`IFT` 其实是通过牺牲某些性能来换取更好的与人类需求对齐的效果。举个例子，`ChatGPT` 擅长聊天对话，但它的上下文学习能力就会相对变差。OpenAI 的研究人员在他们的 `IFT` 论文中把这种现象称为“对齐税”。

3. 训练奖励模型

在InstructGPT的论文中提到，奖励模型其实是一个60亿参数的SFT模型，只不过做了一些调整：
1. 去掉了最后一个非嵌入层。
2. 把`softmax`换成了一个线性层，让它直接输出一个奖励值的标量。

然后，这个模型会基于数据集中的提示词和回复排序来重新训练。当然，我们也可以从头开始训练一个奖励模型，但实验表明：
- 用SFT模型作为起点效果更好
- 训练效率也更高

这很可能是因为SFT模型已经学会了一些NLP的基础知识，所以用它作为起点会更容易训练出好的奖励模型。

在训练奖励模型时，损失函数的输入标签其实是回复的排序，而不是实际的奖励值。所以，我们需要把排序转换成奖励值。这时候你可能会问：**为什么不直接用分类模型，非要绕个弯把排序转换成分数呢？**

---

1. **为什么用排序而不是直接分类？**
   - 排序能更好地反映回复之间的相对优劣，而分类模型只能给出固定的类别标签。
   - 排序可以更灵活地处理不同回复之间的细微差别，而分类模型可能会忽略这些细节。

2. **排序如何转换成奖励值？**
   - 通过设计一个转换机制，将排序映射到具体的奖励分数上。
   - 这种方法可以让模型更准确地学习到哪些回复更好，哪些更差。

---

总结来说，虽然绕了个弯，但把排序转换成分数的方式，能让模型更精准地学习到回复的质量差异。

举个例子，就像我们上学时写作文一样，作文评分是语文考试中最难预测的部分。为什么呢？因为老师的打分往往带有很强的主观性。同一篇作文，不同的老师可能会给出完全不同的分数。这种情况在给`ChatGPT`做标注时也会发生。每个标注员对同一段生成文本的评分可能不一样，这就导致模型在学习时，可能会对同一句话的质量感到困惑，不知道该相信哪个评分。

如果我们把任务从打“绝对分数”改成“相对排序”，就能大大减少标注时的麻烦。具体来说：

1. **不再要求标注员给每句话打一个绝对的分数**，而是让他们对一组答案进行排名。
2. 这样一来，**即使不同标注员对同一句话的质量有不同看法**，他们对一组答案的相对质量排序可能会更一致。
3. 这种方法让标注过程变得更简单、更有效。

换句话说，**从“打分”到“排序”的转变**，解决了标注中的不一致问题，同时提高了标注效率。

解决了标注一致性问题后，我们需要教模型如何从排列好的序列中学习打分。举个例子，假设模型生成了4句话，分别是A、B、C、D，并且标注员已经根据质量给它们排好了顺序：$\mathrm{A}>\mathrm{B}>\mathrm{C}>\mathrm{D}$。我们的目标是训练一个模型，让它给出的分数满足 $r(\mathrm{A})>r(\mathrm{B})>r(\mathrm{C})>r(\mathrm{D})$。

为了实现这个目标，我们可以设计一个特殊的损失函数，比如：

$$10\mathrm{{ss}\ =}\ r({\bf{A}})-r({\bf{B}})+r({\bf{A}})-r({\bf{C}})+r({\bf{A}})-r({\bf{D}})+r({\bf{B}})-r({\bf{C}})+r({\bf{B}})-r({\bf{D}})+r({\bf{C}})-r({\bf{D}})$$

为了让损失值控制在 $0\sim1$ 之间，我们会用Sigmoid函数对每两句话的分数差进行归一化。这样，损失函数的值就等于排序列表中所有前面的“好句子”评分减去后面的“坏句子”评分的总和。

我们的目标是让模型最大化“好句子得分”和“坏句子得分”之间的差值。但由于梯度下降本质上是一个最小化操作，所以我们需要对损失函数取负数，这样才能达到最大化差值的目的。

总结一下：
- 模型需要学习根据排列好的序列打分。
- 损失函数的设计目标是让好句子的得分高于坏句子。
- 使用Sigmoid函数归一化分数差，确保损失值在合理范围内。
- 通过取负数的方式，将最大化问题转化为最小化问题，从而适配梯度下降算法。

具体来说，对于一个提示词，我们取出一对答案，分别记为 $y_{w}\setminus y_{1}$，并且假设 $y_{w}$ 的排序比 $y_{1}$ 更高。接下来，我们通过以下步骤来计算损失函数：

1. 使用提示词 $x$ 和答案 $y_{w}$ 通过奖励模型得到一个分数 $r_{\theta}(x,y_{w})$。
2. 使用提示词 $x$ 和答案 $y_{1}$ 通过奖励模型得到另一个分数 $r_{\theta}(x,y_{1})$。

由于 $y_{w}$ 的排序比 $y_{1}$ 高，我们希望 $r_{\theta}(x,y_{w})$ 的值比 $r_{\theta}(x,y_{1})$ 更大。为了衡量这一点，我们通过 Sigmoid 函数进行计算，然后取对数，最终得到逻辑回归的损失函数，即：

$$
\text{损失函数} = \log(\text{Sigmoid}(r_{\theta}(x,y_{w}) - r_{\theta}(x,y_{1})))
$$

这个过程帮助我们优化模型，使其更倾向于选择排序更高的答案。

$$
\displaystyle\cos(\theta)\!=\!-\frac{1}{\binom{K}{2}}E_{(x,y_{w},y_{1})\sim D}[\log(\sigma(r_{\theta}(x,y_{w})\!-r_{\theta}(x,y_{1})))]
$$

对于每个提示词，模型会生成 $K{=}9$ 个答案，每次从 $K$ 里面选出来两个，最终除以组合数进行标准化。

图14展示了OpenAI标注员在创建InstructGPT奖励模型训练数据时使用的用户界面（UI）示例。标注员的工作流程如下：

1. 对每个回答进行评分，评分范围是 `1~7` 分。
2. 根据他们的偏好对回答进行排序。

需要注意的是，对于训练过程来说，只有排序信息是真正有效的。在标注的一致性方面，大约能达到 `73%`。这意味着：

- 如果有10个人对两个回答进行排序，
- 其中大约有7个人会得到完全一致的结果。

这个数据点说明了标注员之间的一致性水平。

4. 强化学习微调

ChatGPT 和 InstructGPT 的训练方法都采用了 RLHF（人类反馈强化学习），但它们在数据收集方面有一些不同。RLHF 把语言模型的微调过程变成了一个强化学习问题，并用 PPO 算法来处理。为了做到这一点，我们需要定义几个关键元素：

1. **策略**：这是指基于已有的语言模型，接收提示词（输入），然后生成一系列文本或文本的概率分布。
2. **动作空间**：这是所有可能的词汇在所有输出位置上的组合。通常，每个位置有大约 50,000 个词汇选项。
3. **观察空间**：这是所有可能的输入词汇序列，也就是提示词。
4. **奖励函数**：这个函数是通过预训练好的奖励模型来计算的，同时还会考虑一些策略层面的约束。

简单来说，RLHF 通过强化学习的方式，让模型学会根据提示词生成更符合人类期望的文本。

![](https://gitee.com/Ace_bb/static_resource_cloud/raw/master/LLMBook/LLMBOOK1/images/2f6f1b5490da546d4046449c40e1340b9b68782a2f7d4d45452392288af8cef6.jpg)
图14 创建奖励模型训练数据时的用户界面示例

强化学习微调的流程如图1所示。具体步骤如下：

1. **选择提示并生成输出**：
   - 从预先准备好的数据中挑选一个提示。
   - 将这个提示分别输入到两个模型中：
     - 初始的语言模型
     - 当前正在训练的语言模型
   - 得到两个模型的输出文本，分别记为 $y_{1}$ 和 $y_{2}$。

2. **评分与比较**：
   - 使用奖励模型对 $y_{1}$ 和 $y_{2}$ 进行评分，判断哪个输出更优秀。
   - 计算两个评分的差值，这个差值将作为训练策略模型的信号。

3. **计算奖励或惩罚**：
   - 基于评分差值，通常通过KL散度来计算奖励或惩罚的大小。
   - 如果 $y_{2}$ 的评分比 $y_{1}$ 高出很多，奖励会更大；反之，惩罚会更大。

4. **更新模型参数**：
   - 根据计算出的奖励，使用PPO算法来更新模型的参数。

通过这个过程，模型逐步优化，生成更符合预期的输出。

![](https://gitee.com/Ace_bb/static_resource_cloud/raw/master/LLMBook/LLMBOOK1/images/b390282b8ecd90e756cc80cafe71f816980a9f1a770787bae5c21b0ba7c0ef1e.jpg)
图1 强化学习微调流程示意图

为什么要加入 KL 散度这个限制呢？原因其实很简单：OpenAI 发现，在训练过程中，模型不能偏离初始预训练模型和有监督微调阶段的模型太多。这个限制就是通过 KL 散度在目标函数中实现的。

具体来说，添加这个限制的原因有以下几点：

1. **多个可能的回答**：对于任何一个提示，可能存在多个合理的回答。然而，大部分回答可能是奖励模型从未见过的。
2. **奖励模型的局限性**：对于这些未见过的提示和回答对，奖励模型可能会给出错误的评分，比如极高或极低的分数。
3. **避免错误选择**：如果没有这个限制，模型可能会倾向于选择那些得分极高的回答，但这些回答实际上可能并不优质。

因此，加入 KL 散度这个限制条件，可以帮助我们避开那些可能并不优质但得分极高的回答，从而让模型的表现更加稳定和可靠。

强化学习微调模型时的目标函数如下

$$
\mathrm{objective}(\phi)=E_{(x,y)\sim D_{\pi_{\phi}^{\mathrm{RL}}}}\left[r_{\theta}(x,y)-\beta\log\left(\frac{\pi_{\phi}^{\mathrm{RL}}(y\mid x)}{\pi^{\mathrm{SFT}}(y\mid x)}\right)\right]+\gamma E_{x\sim D_{\mathrm{petan}}}[\log\pi_{\phi}^{\mathrm{RL}}(x)]
$$


- `$\pi_{\phi}^{\mathrm{RL}}$`：这是一个可以学习的策略。
- 在初始化时，`$\pi_{\phi}^{\mathrm{RL}}$` 和 `$\pi^{\mathrm{SFT}}$` 是完全一样的。


- `$\pi^{\mathrm{SFT}}$`：这是通过**有监督学习微调**训练出来的模型。简单来说，就是先用标注好的数据对模型进行训练，让它学会如何根据输入生成正确的输出。

- `$E_{(x,y)\sim D_{\pi_{\phi}^{\mathrm{RL}}}}$`：这里的 `$(x,y)$` 是从**当前的强化学习模型**中采样得到的。具体来说：
  - 每个提示词 `$x$` 都会通过模型生成一个对应的输出 `$y$`。
  - 然后，系统会对这对 `$(x,y)$` 进行打分。
  - 最终的目标是通过**最大化这个分数**来更新模型的参数，让模型的表现越来越好。

总结一下：
1. `$\pi^{\mathrm{SFT}}$` 是通过有监督学习微调得到的模型。
2. `$E_{(x,y)\sim D_{\pi_{\phi}^{\mathrm{RL}}}}$` 表示从强化学习模型中采样 `$(x,y)$`，并通过打分机制优化模型参数。

- `$r_{\theta}$` 是一个固定的值，不会发生变化。
- 它的训练数据分布来自 `$\pi^{\mathrm{SFT}}$`。
- 当 `$\pi_{\phi}^{\mathrm{RL}}$` 更新时，可能会导致 `$y$` 的分布发生变化。
- 这种变化会让 `$r_{\theta}$` 的估算逐渐变得不准确。
- 为了解决这个问题，使用 KL 散度 `$\beta\log\left(\frac{\pi_{\phi}^{\mathrm{RL}}(y\vert x)}{\pi^{\mathrm{SFT}}(y\vert x)}\right)$` 来控制更新的幅度。

过于专注微调任务可能会导致模型偏移，因此又从GPT-3 的训练数据集中采样了一些数据，用于语言模型损失函数：

$$
\gamma E_{_{x\sim D_{\mathrm{pretain}}}}[\log\pi_{_{\phi}}^{\mathrm{RL}}(x)]
$$

如果 $\gamma=0$，那么模型就是一个纯粹的 `PPO` 模型；如果 $\gamma\neq0$，那么模型就变成了混合训练的 `PPO` 模型，在论文里，这种模型被称为 `PPO-ptx`。

虽然强化学习在自然语言处理（NLP）领域表现出了很大的优势，但它也存在不少问题，比如训练速度慢、成本高等。特别是在现实世界中，很多任务的探索成本或数据获取成本都很高，所以如何提高训练效率是强化学习领域需要解决的一个重要问题。

大语言模型在进行RLHF（人类反馈强化学习）中的PPO（近端策略优化）训练时，会遇到很多困难。这些困难主要体现在以下几个方面：

1. **计算资源消耗大**：训练过程需要大量的计算资源。
2. **训练稳定性差**：模型在训练过程中可能会出现不稳定的情况，比如：
   - 变成“复读机”，一直输出没有逻辑的内容。
   - 变得“沉默寡言”，几乎不输出任何内容。

类似的问题在强化学习游戏训练中也很常见。如果环境和参数设置得不好，智能体可能会走向极端，导致训练过程变得非常困难。

在这方面，复旦大学的一篇技术报告非常值得参考。这篇报告不仅分享了一些关键技巧和设置，还详细记录了训练过程中遇到的失败经验。这些内容对我们理解和改进模型的 RLHF（基于人类反馈的强化学习）训练过程非常有帮助。如果你想深入了解，可以查看报告的链接：[https://arxiv.org/abs/2307.04964](https://arxiv.org/abs/2307.04964)。

总结一下，这篇报告的价值主要体现在以下两点：
1. **关键技巧和设置**：提供了实用的训练方法和参数配置。
2. **失败经验**：记录了训练过程中遇到的问题和解决方案，帮助我们避免类似错误。

通过这些内容，我们可以更好地优化模型的训练过程。

5. 为什么要用强化学习训练？

为什么InstructGPT的训练非得用强化学习，而不是直接用一步有监督学习搞定呢？大部分模型都是“一步到位”的，也就是直接通过一种方式训练出一个模型。就算是“预训练 $^+$ 微调”这种模式，也只需要两步就完事了。很少有模型像InstructGPT这样，在微调阶段就分成了三步，还得训练出3个模型。那么，为什么要搞这么复杂呢？是因为强化学习比有监督学习效果更好吗？还是说单纯用有监督学习还不够？下面我们来仔细分析一下这个问题。

---

### 关键点分析：
1. **大部分模型的特点**：
   - 通常是一步到位的端到端训练。
   - 即使是“预训练 $^+$ 微调”模式，也只需要两步。

2. **InstructGPT的特殊性**：
   - 微调阶段分成了三步。
   - 需要训练3个模型。

3. **核心问题**：
   - 为什么不用一步有监督学习？
   - 强化学习是否比有监督学习效果更好？
   - 单纯有监督学习是否不够？

通过这些问题，我们可以更深入地理解InstructGPT的设计思路。

经过预训练的 GPT-3 模型在文本生成方面表现非常出色。它能根据你提供的前文生成后续内容，但这些生成的内容只是更符合自然语言的规律，从数学角度来看，也只是出现概率较高的结果，并不一定完全符合实际交流的需求。

举个例子：
- 如果你输入的前文是一个问题，模型可能会：
  - 直接回答这个问题；
  - 生成一系列与问题相关的问题；
  - 或者开始介绍问题的背景。

这些生成的内容都是遵循自然语言规律的合理延续，但可能并不完全符合你的预期。

为了改善这种情况，我们可以对前文进行一些定制化处理，让模型生成更符合我们期望的结果。这种方法被称为“提示词工程”。比如：
- 如果你想问“什么是 AIGC？”，你可以输入这样的前文：`问题：什么是 AIGC？回答：`。
- 这样，模型就更有可能生成你想要的答案。

不过，对于普通用户来说，这种方式可能不太方便，因为他们更希望直接提出问题或发布指令就能得到答案，而不需要额外设计提示词。

这就引出了为什么InstructGPT需要第一步的有监督微调。如果我们想让模型持续回答问题，就需要对它进行引导，这个过程就是微调，也有人称之为“对齐模型与用户需求”。具体来说，我们需要做以下几件事：

1. **收集数据**：我们需要一组由人类编写的文本，这些文本包含问题或指令，并且附带期望的输出结果。
2. **训练模型**：用这些数据训练模型，让它在给定前缀（比如问题或指令）的情况下预测下文（也就是输出）。
3. **学习“指令-输出”关系**：这次的训练基于“指令–输出”对的集合，模型会学会通过执行指令来生成相应的输出。换句话说，我们会向模型展示问题和正确输出的对应关系，让它学会“复制”这些输出结果。

通过这种方式，我们希望模型能够泛化到训练中没见过的其他问题上。

经过预训练和有监督微调后，模型已经变得非常强大了，能够应对各种指令和问题。不过，它仍然存在一些不足：

- **InstructGPT 的回答可能过于模板化**：它倾向于复制我们提供的标准答案，这限制了它的创造力，甚至可能让它变成一个“模板复读机”。
- **原因在于有监督微调的限制**：在微调过程中，只要模型生成的结果稍微偏离我们给定的答案，就会受到惩罚。这导致模型变得非常“小心翼翼”，不敢自由发挥。
- **人类语言的多样性**：人类的语言可以通过多种方式传递信息，因此我们希望模型不仅能生成符合模板的回答，还能超越模板，创造出符合人类对话模式和价值取向的创新性回答。

总结来说，虽然模型已经很强大，但在创造力和灵活性方面还有提升空间。

想要让大语言模型产生更多创意，就像做试卷最后的附加题一样。如果只是按照常规的学习模板来解题，可能得不到正确答案。这时候，就需要一些“脑洞大开”的想法。如果能给出创新的回答，就能拿到更高的分数。这也是为什么我们需要第二步的奖励模型和第三步的强化学习。

在强化学习阶段，我们不再要求模型按照我们提供的对话范例一个字一个字地接龙，而是直接向它提问，让它自由发挥。如果它的回答很棒，就给它奖励；如果回答得不好，就降低奖励。然后，我们会根据这些评分去调整模型。这就是强化学习比有监督学习更有优势的地方：有监督学习只能提供正反馈，而强化学习既能提供正反馈，也能提供负反馈。

举个例子：
- **有监督学习**：就像做题时，老师给了一道题，还附上了标准答案。我们所有的解题步骤都在向这个标准答案靠拢。即使思路不对，最后也能硬凑出结果。
- **强化学习**：则像老师给了一道题，但没有给答案。我们想出一种解决方案后，让老师打分。如果思路错了，得分肯定不高。通过排除错误方案，最终剩下的就是正确的思路和答案。

总结一下：
- 强化学习让模型更自由地发挥，而不是被固定的范例限制。
- 通过奖励和惩罚机制，模型可以逐步优化自己的回答。
- 这种方式比单纯的有监督学习更灵活，也更能激发创意。

但是，相比于有监督训练，强化学习要难得多。主要原因之一是强化学习中存在一个叫“**credit 分配**”的问题。具体来说，当语言模型生成一段词元序列时，它只能在序列的末尾得到一个分数。这个分数信号比较弱，导致我们无法判断生成的答案中哪些部分是好的，哪些部分是不好的。这就让强化学习变得更加复杂。不过，这个问题我们暂时先不深入讨论。

通过这三步训练之后，模型的表现得到了显著提升，既不会被模板规范限制，又能在引导下生成符合人类认可的高质量回答，甚至还具备了一些意想不到的能力。具体来说：

1. **回答更加详尽**  
   相比于之前的版本，模型生成的文本变得更长。以`ChatGPT`为例，它的回答常常会变得非常冗长，以至于用户需要明确要求“用一句话回答我”才能得到简洁的答案。

2. **回答更加公正和平衡**  
   当问题涉及多个实体利益的事件时（比如政治事件），模型能够提供更加公正和平衡的回答。

3. **拒绝不当问题的能力**  
   模型还具备了拒绝不当问题的能力。这种能力是通过以下两步实现的：
   - 首先，内容过滤器会过滤掉一部分问题。
   - 然后，模型在此基础上进一步拒绝不适当的内容。  
   这种机制提高了模型对问题的筛选和拒绝能力。

总结来说，这些改进让模型在生成回答时更加灵活、全面，同时也更符合人类的期望。

还有一个让人意想不到的能力，就是大语言模型能够拒绝回答它知识范围之外的问题。举个例子，早期的 `ChatGPT` 会直接拒绝回答 2021 年 6 月之后发生的新事件相关的问题，因为它没有在这些新数据上训练过。这个功能其实是 `RLHF`（基于人类反馈的强化学习）最神奇的地方，它让模型能够隐式地分辨哪些问题在它的知识范围内，哪些问题不在。

不过，要实现这个功能并不简单。虽然我们可以通过有监督学习来约束模型的行为，比如告诉它不要回答涉及种族歧视的问题，并尝试让它回答“我不知道”，但这只是一个简单的替代方案，并不能保证在所有未知情况下都能得到理想的回答。而且，在强化学习中，这个功能也很难实现，因为模型可能从一开始就不会生成“我不知道”这样的答案，我们很难直接鼓励它这么做。

所以，`RLHF` 的解决方法是分两步走：
1. 先进行有监督训练，让模型学会在某些情况下回答“我不知道”。
2. 再进行强化学习训练，让模型学会在什么情况下应该回答“我不知道”。

不过，这种方法也有一些缺点。比如，模型可能会过度使用“我不知道”，导致无法提供有用的回答。因此，如何设计奖励函数就成了一个重要的研究问题。我们可以尝试这样设计：
- 对正确答案给出非常高的分数。
- 对放弃回答的答案（比如“我不知道”）给出中低分。
- 对错误答案给出负分。

通过这种方式，我们可以更好地引导模型的行为。

在论文的结尾部分，研究者们对 `InstructGPT` 进行了详细的评估，并总结了一些关键发现：

1. **整体表现**：标注员们普遍认为，`InstructGPT` 的输出质量比 `GPT-3` 要好得多。
2. **真实性提升**：`InstructGPT` 在回答的真实性上比 `GPT-3` 有明显的进步。
3. **内容控制**：在减少生成不良内容方面，`InstructGPT` 比 `GPT-3` 有所改进，但仍然存在一些偏见问题。
4. **泛化能力**：`InstructGPT` 能够很好地扩展到训练数据集之外的预留数据和指令上，表现出较强的泛化能力。
5. **改进空间**：尽管有这些进步，`InstructGPT` 仍然会犯一些简单的错误，说明它还有进一步优化的潜力。

总结来说，`InstructGPT` 在多个方面优于 `GPT-3`，但仍有一些问题需要解决。

### 2.4.4 RLAIF


RLHF（基于人类反馈的强化学习）是一种让语言模型更好地符合人类偏好的技术，它是现代对话语言模型成功的重要推动力之一。不过，RLHF 面临的一个主要挑战是：它需要大量高质量的人工标注数据。


谷歌的一项研究发现，在大语言模型的训练过程中，AI 可以替代人类反馈。具体来说，谷歌提出了一种新的方法，叫做基于 AI 反馈的强化学习（RLAIF），相关研究发表在论文《RLAIF: Scaling Reinforcement Learning from Human Feedback with AI Feedback》（[论文链接](https://arxiv.org/abs/2309.00267)）中。实验结果显示，RLAIF 的表现与传统的基于人类反馈的强化学习（RLHF）非常接近。

这一发现有两个重要意义：
1. 它可能让人类从大语言模型的训练流程中进一步解放出来。
2. 它让“AI 训练 AI”这一构想离现实更近了一步。

简单来说，这项研究表明，AI 不仅能学习，还能教其他 AI，而且效果和人类教的差不多。

RLAIF 是一种利用现有大语言模型（LLM）生成偏好标签的方法。具体来说，它的工作流程是这样的：

1. **生成偏好标签**：
   - 比如，给出一段文本和两个候选摘要，谷歌会用现成的 `LLM` 来判断哪个摘要更好，并给出排序结果。

2. **训练奖励模型**：
   - 基于这些偏好标签，模型会使用对比损失来训练一个奖励模型。

3. **微调策略模型**：
   - 最后，通过强化学习，利用这个奖励模型来微调出一个策略模型。
