# Prefix-tuning

Prefix-Tuning（前缀微调）是一种软提示方法，出自论文《Prefix-Tuning: Optimizing Continuous Prompts for Generation》（[论文链接](https://arxiv.org/abs/2101.00190)）。我们来看一下它的特点：

1. **Prefix-tuning的特点**：
   - 冻结预训练模型的参数，不进行更新。
   - 通过添加可训练的、针对特定任务的前缀来适应不同任务。
   - 存储时只需保存前缀部分，大大降低了微调的成本。

总结来说，前缀微调通过只调整前缀部分，既保留了预训练模型的能力，又减少了存储和计算的开销。

Prefix-Tuning 的工作原理和 GPT-3 的上下文学习有点像，但两者之间有一些关键区别：

1. **上下文学习的提示词**：
   - 在 GPT-3 的上下文学习中，前缀是人工设计的离散提示词。
   - 这些提示词对最终输出非常敏感，多一个词或少一个词都会对结果产生很大影响。

2. **Prefix-Tuning 的提示词**：
   - Prefix-Tuning 为每个任务添加的前缀是连续可微的提示词。
   - 这些提示词不会直接体现在输入上，而是被添加到模型的嵌入层。
   - 具体来说，它用可微分的虚拟词元替换了人工设计模板中的真实词元。

3. **数学表达**：
   - 原本的公式是 $\scriptstyle{Y=W X}$。
   - 在 Prefix-Tuning 中，$W$ 被替换为 $W^{\prime}=[W_{\mathrm{p}};\,W]$，公式变为 $\scriptstyle{Y=W^{\prime}X}$。

简单来说，Prefix-Tuning 通过引入连续可微的提示词，让模型在嵌入层中更灵活地适应不同任务，而不是依赖固定的离散提示词。

Prefix-Tuning 的研究者发现，直接优化添加的前缀参数会导致训练不稳定和模型效果下降，因此又增加了一个MLP 映射：

$$
h_{i}=\left\{\begin{array}{l l}{P_{\theta}[i,:]=\mathrm{MLP}_{\theta}(P_{\theta}^{\prime}[i,:]),i\in P_{\mathrm{idx}}}\\ {\mathrm{LM}_{\phi}(z_{i},h_{<i}),i\in P_{\mathrm{idx}}}\end{array}\right.
$$

Prefix-Tuning 针对不同的模型架构设计了不同的前缀结构。具体来说：

1. **自回归架构模型（如 GPT）**：
   - 在句子前面添加前缀。
   - 输入序列的形式为：`[PREFIX; $x; y]$`。

2. **编码器–解码器架构模型（如 BART）**：
   - 在编码器和解码器的输入中都增加前缀。
   - 输入序列的形式为：`[PREFIX; $x$; PREFIX'; y]`。
   - 其中：
     - 编码器端的前缀用于引导输入部分的编码。
     - 解码器端的前缀用于引导后续 token 的生成。

这种设计使得 Prefix-Tuning 能够灵活适应不同模型架构的需求。

在微调大语言模型时，前缀的作用非常重要。它就像是给模型的一个“提示”，帮助模型更好地理解输入信息，从而生成更准确的输出。具体来说：

- 在**文本摘要任务**中，经过微调的前缀会引导模型从输入中提取出关键信息，然后生成简洁的摘要。
- 在**情感分类任务**中，前缀则会引导模型专注于输入中与情感相关的内容，从而更准确地判断情感倾向。

简单来说，前缀就像是一个“导航仪”，告诉模型该往哪个方向“看”，以便更好地完成任务。

在实际应用中，前缀添加的词元数量是一个需要仔细调整的超参数。虽然直接在嵌入层添加前缀很简单，但这种方式引入的可训练参数较少，效果可能不如在每一层都加入前缀。因此，在Prefix-Tuning的研究中，研究者设计了以下3个实验：

1. **全量微调**：对整个模型进行微调。
2. **Embedding-only 前缀微调**：只在前两个嵌入层加入前缀并进行微调。
3. **Full 前缀微调**：在所有层都加入前缀并进行微调。

实验结果如下：
- **Embedding-only 前缀微调**的效果比全量微调略好。这可能是因为全量微调容易导致“灾难性遗忘”问题，而前缀微调更倾向于保留预训练模型的能力。
- **Full 前缀微调**的性能明显优于**Embedding-only 前缀微调**。这可能是因为Full前缀微调引入了更多的可学习参数，从而提升了模型的表现。

Prefix-Tuning 有两大明显的优势：

1. **采用连续可微的软提示设计**  
   它不再使用传统的人工或半自动的离散空间硬提示设计，而是通过端到端的优化方式，在连续可微的空间中学习不同任务对应的 `prompt` 参数。

2. **性能优于其他微调方法**  
   与 Adapter 等其他微调方法相比，在优化参数数量相同的情况下，Prefix-Tuning 的表现更好，甚至能够达到与全量微调相当的效果。

然而，`Prefix-Tuning` 也有一些问题和限制：

1. **训练难度较高**：模型的性能并不一定会随着前缀参数量的增加而变得更好，训练过程可能会比较复杂。
2. **数据空间受限**：添加前缀后，原始文字数据的可用空间会减少，这可能会影响原始文字中提示词的表现能力。

核心思想是在模型的输入词的嵌入向量前增加了一个Prefix Token，即前缀向量，这种前缀不是自然语言，而是向量形式的Token，被称为虚拟Token。为了保证这些虚拟Token的有效性，Prefix-tuning在Transformer的所有层中都增加了这种前缀向量。新增的一系列向量连续的、可训练的任务特定前缀（prefix），通过这些前缀来引导模型的注意力和生成过程，而不需要对模型的主体参数进行更新。
技术特点
1）参数效率：Prefix Tuning 只需要对前缀参数进行训练，而模型的主体参数保持不变，大大减少了需要训练的参数数量。
2）动态更新：在训练过程中，Prefix Tuning 动态地选择需要更新的参数，从而逐步引导模型适应特定任务。
3）任务特定：前缀是针对特定任务设计的，可以有效地引导模型的注意力，使其更专注于任务相关的信息。
4）连续可微：与基于离散模板的方法相比，Prefix Tuning 使用的是连续的向量序列，这使得优化过程更加稳定和高效。
