## P-Tuning

P-Tuning 是一种软提示方法，出自论文《GPT Understands, Too》（[论文链接](https://arxiv.org/abs/2103.10385)）。它的主要目标是解决离散提示词搜索对输入变化过于敏感的问题。P-Tuning 的思路和 Prefix-Tuning 很像，都是通过添加可微分的虚拟词元来实现的。不过，P-Tuning 只在输入部分添加这些虚拟词元，而不是在模型的每一层都添加。

另外，P-Tuning 的虚拟词元位置非常灵活，不一定要放在前缀部分，可以根据需要放在中间或最后，具体可以参考图6b 的展示。

图6 提示词搜索“The capital of Britain is [MASK]”

给定一个上下文（比如 `Britain`）和一个目标（`[MASK]`），剩下的部分就是我们需要搜索的提示词。我们可以通过以下两种方式来理解提示词的生成和优化：

1. **图6a**：提示词生成器只能接收到**离散的奖励信号**。这意味着它的反馈是有限的，只能通过简单的信号来调整提示词的生成。

2. **图6b**：**P-Tuning** 则可以通过多种方式优化**虚拟词元**和**提示词编码器**。这种方法更加灵活，能够更好地调整提示词的生成过程。

简单来说，提示词的生成和优化可以通过不同的方式实现，而 P-Tuning 提供了更多的优化手段。

由于预训练后的嵌入层参数通常是高度离散的，如果随机初始化虚拟词元，模型容易陷入局部最优解。P-Tuning 的研究者认为，插入的虚拟词元之间应该存在某种关联性，因此如何准确建模这些关系是一个关键问题。

在实验中，P-Tuning 的研究者发现，使用一个提示词编码器（由 `LSTM` 和 `MLP` 组成）来编码虚拟词元，可以让模型更快地收敛。具体来说：
- `LSTM` 的作用是重参数化，从而加速训练过程。
- `MLP` 则进一步处理 `LSTM` 的输出，公式表示为：$$h_{i}=\mathrm{MLP}([\mathrm{LSTM}(h_{0:i})\colon\mathrm{LSTM}(h_{i:m})])$$。

此外，P-Tuning 还引入了一些自然语言提示词作为锚字符（例如图6 中的“Britain”），这些锚字符进一步提升了模型的表现效果。

实验结果显示，P-Tuning 在微调效果上不仅能够和全量微调打个平手，甚至在某些任务中表现得更出色。P-Tuning 有以下几个特点：

1. **放弃自然语言模板的限制**：它不再要求模板必须由自然语言构成，而是用虚拟的 `token` 来构建软提示。
2. **端到端优化**：通过端到端的方式，在连续空间里优化 `prompt` 参数，这让它在自然语言理解任务中表现得非常出色。
3. **性能提升**：得益于这种方法，GPT 在这类任务上的性能可以和 BERT 一较高下，甚至在某些情况下还能超越 BERT。
4. **虚拟标记的依赖关系**：P-Tuning 还考虑了虚拟标记之间的依赖关系，并引入了一个提示词编码器（LSTM）来刻画这种关系。
5. **混合提示策略**：它指定了一些上下文词作为虚拟标记的初始化，并采用了混合提示策略，将连续提示和离散的 `token` 结合起来使用。

总的来说，P-Tuning 通过一系列创新设计，显著提升了模型在自然语言理解任务中的表现。

然而，P-Tuning 这种微调方法并不是在所有情况下都适用。通过实验我们发现：

1. **模型规模的影响**：
   - 当模型的参数规模超过 100 亿时，P-Tuning 的效果可以媲美全量微调。
   - 但对于参数规模较小的模型，P-Tuning 的表现和全参数微调相比差距较大。

2. **跨任务的通用性问题**：
   - P-Tuning 在序列标注任务中的有效性没有得到验证。
   - 序列标注任务需要预测一系列标签，而这些标签大多没有实际意义，这对 P-Tuning 方法来说是一个挑战。

3. **可调参数量的限制**：
   - P-Tuning 的虚拟词元只插入到模型最开始的嵌入层。
   - 由于输入序列的长度有限，导致可调参数量也受到限制。

4. **模型层数的影响**：
   - 当模型层数较多时，微调的稳定性难以保证。
   - 模型层数越多，第一层输入的提示词对后面层的影响就越难以预测。

总结来说，P-Tuning 虽然在某些场景下表现不错，但在模型规模较小、跨任务通用性、可调参数量以及模型层数较多的情况下，仍然存在一些局限性。



P-Tuning（基于提示的微调）和提示调整都是为了调整大型预训练语言模型（如GPT系列）以适应特定任务而设计的技术。两者都利用预训练的语言模型执行特定的下游任务，如文本分类、情感分析等，并使用某种形式的“提示”或“指导”来引导模型输出，以更好地适应特定任务。

提示调整与P-Tuning的主要区别在于：

- 提示调整：使用静态的、可训练的虚拟标记嵌入，在初始化后保持固定，除非在训练过程中更新。这种方法相对简单，因为它只涉及调整一组固定的嵌入参数，在处理多种任务时表现良好，但可能在处理特别复杂或需要细粒度控制的任务时受限。
- P-Tuning：使用一个可训练的LSTM模型（称为提示编码器prompt_encoder）来动态生成虚拟标记嵌入，允许根据输入数据的不同生成不同的嵌入，提供更高的灵活性和适应性，适合需要精细控制和理解复杂上下文的任务。这种方法相对复杂，因为它涉及一个额外的LSTM模型来生成虚拟标记嵌入。

P-Tuning中使用LSTM（长短期记忆网络）作为生成虚拟标记嵌入的工具，利用了LSTM的以下优势：

- 更好的适应性和灵活性：LSTM可以捕捉输入数据中的时间序列特征，更好地理解和适应复杂的、顺序依赖的任务，如文本生成或序列标注。
- 改进的上下文理解：LSTM因其循环结构，擅长处理和理解长期依赖关系和复杂的上下文信息。
- 参数共享和泛化能力：在P-Tuning中，LSTM模型的参数可以在多个任务之间共享，这提高了模型的泛化能力，并减少了针对每个单独任务的训练需求。而在提示调整中，每个任务通常都有其独立的虚拟标记嵌入，这可能限制了跨任务泛化的能力。

这些特性使得LSTM特别适合处理复杂任务和需要细粒度控制的应用场景。然而，这些优势也伴随着更高的计算复杂度和资源需求，因此在实际应用中需要根据具体需求和资源限制来权衡使用LSTM的决策。
